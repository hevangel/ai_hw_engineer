# Shared Intel 8253/8254 timer with incomplete BCD and sign-off coverage

The change adds one synthesizable timer module whose `IS_8254` parameter genuinely selects the documented byte-phase and read-back variants, plus specifications, simulation, formal wrappers, scripts, and reports. The pinned aggregate flow reproduces its lint, simulation, formal, and synthesis PASS results. The design is not ready because packed-BCD Mode 3 is behaviorally wrong, two sampled-event corners contradict the specification, and verification/reporting claims exceed the implemented oracles. Watch for: **confirmed HIGH** BCD Mode 3 corruption; **confirmed HIGH** formal and report overclaim that masks timer-engine defects; **confirmed MEDIUM** Mode 4 low-strobe extension under low GATE; **confirmed MEDIUM** stale Mode 1/5 triggers captured before a count is armed.

**Verdict**: NEEDS_CHANGES

## High-level view

The one-module architectural requirement is satisfied. Both simulation instances and both formal wrappers elaborate `intel_8253_8254`; constant `IS_8254` branches select independent versus shared read/write phase and enable versus ignore read-back, with no duplicated timer engine.

**Confirmed HIGH:** Mode 3 bypasses the packed-BCD helper for its decrement-by-one/two/three operations. Decimal counts crossing a nibble boundary become invalid BCD and produce the wrong waveform period.

**Confirmed MEDIUM:** Mode 4 restores its terminal low strobe only while GATE is high, despite the next-clock recovery contract. **Confirmed MEDIUM:** Modes 1 and 5 retain GATE edges observed before a complete count write and can start without a post-arm edge.

**Confirmed HIGH:** formal proves only bus-drive legality, reset/programming OUT, and partial status metadata, while plans and reports describe broad timer-engine proofs. **Confirmed HIGH:** simulation/report closure also includes scenarios absent from the testbench, so green tool status is not behavioral sign-off.

<details><summary>Details</summary>

## Packed-BCD Mode 3 falls back to binary subtraction

The specification exposes packed four-decade BCD for all modes and defines Mode 3 through a historical subtract-by-two image. The RTL's BCD-aware helper is at `design/intel_8253_8254/src/intel_8253_8254.sv:67-99`, but Mode 3 directly executes `count_value - 1`, `- 3`, and `- 2` at `design/intel_8253_8254/src/intel_8253_8254.sv:440-462`. **Confirmed HIGH:** `16'h0010` becomes `16'h000e` on subtract-by-two, so the count ceases to be decimal and the phase duration is wrong; BCD `0000`, representing 10,000, wraps through binary values.

All-mode simulation uses binary (`design/intel_8253_8254/tb/tb_top.sv:303-305`), BCD scenarios use only Mode 0 (`design/intel_8253_8254/tb/tb_top.sv:591-606`), and stress forces BCD off (`design/intel_8253_8254/tb/tb_top.sv:673-675`). No formal assertion observes count evolution or decimal nibbles despite `design/intel_8253_8254/plans/formal_plan.md:23`.

## Mode 4 recovery remains conditional on GATE

Mode 4's `!out_state` recovery is nested under `counting && gate_i` at `design/intel_8253_8254/src/intel_8253_8254.sv:467-491`. **Confirmed MEDIUM:** taking GATE low during the terminal strobe prevents later sampled counter-clock events from restoring OUT, extending the pulse until GATE returns high. This contradicts `design/intel_8253_8254/spec/spec.md:147`, where GATE pauses decrementing but the next counter-clock event restores OUT and stops the one-shot. Recovery from an already-low strobe should precede the GATE-controlled decrement path, with a regression that lowers GATE before recovery.

## Modes 1 and 5 can consume a pre-arm GATE edge

The generic event block sets `trigger_pending` on Mode 1/2/3/5 GATE rises at `design/intel_8253_8254/src/intel_8253_8254.sv:322-332` without requiring a completed reload. Count completion sets `reload_valid` at lines 238, 258, and 292 without clearing a stale trigger. **Confirmed MEDIUM:** after programming Mode 1 or 5, a pre-completion GATE rise remains pending; the next falling clock after the write starts the timer without a post-arm rise, contrary to the arm-then-trigger contract at `design/intel_8253_8254/spec/spec.md:135,151`. Every `trigger_with_clock` test occurs after `program_counter`, leaving this ordering uncovered.

## Fifteen proof outputs do not represent the fifteen planned obligations

The plan names isolation, aliases, mode timing, GATE behavior, latch stability, null count, independent phases, ignored 8253 read-back, and BCD at `design/intel_8253_8254/plans/formal_plan.md:10-23`. The property module at `design/intel_8253_8254/formal/intel_8253_8254_props.sv:34-83` asserts only legal output enable, zero undriven data, reset OUT, OUT after control writes, and status bits 7 and 5:0; it omits null-count bit 6 and never observes timer clocks, GATE, counts, latches, or phases.

**Confirmed HIGH:** `15/15 assertion outputs` counts generated instances of that narrow set, not the fifteen planned behaviors. In the 8253 elaboration, six status assertions are unreachable because `status_pending` is only set under `IS_8254`. The seven covers at `design/intel_8253_8254/formal/intel_8253_8254_cover.sv:84-95` cover Mode 0/1/2 flags, any count write followed by any read, reset, and occurrence of a read-back command; they do not cover Mode 3, Mode 4, Mode 5, BCD, count latching, phases, or behavioral read-back. This gap lets the confirmed RTL defects pass unbounded proof and cover.

## Simulation closure and reports exceed implemented scenarios

**Confirmed HIGH:** `design/intel_8253_8254/report/coverage_report.md:25-34` marks isolation, zero-count programming, retrigger, and read-back forms closed, but the testbench never programs a zero count, retriggers an active Mode 1/5 timer, issues count-only read-back, or asserts untouched-counter stability. The stress loop at `design/intel_8253_8254/tb/tb_top.sv:655-684` only programs a small binary count, triggers or pulses once, optionally pulses again, and compares variant OUT vectors; it performs none of the advertised reads, latches, idles, BCD operations, or independent expected-value checks.

`design/intel_8253_8254/report/coverage_report.md:52` attributes Mode 3, Modes 4/5, latching, BCD, and variant behavior to causal covers that lack those points. `design/intel_8253_8254/report/final_report.md:69-80` similarly claims formal checks not present in the property source. The exact pinned-image `run_all.sh` flow was rerun and passed, confirming an oracle-sufficiency/reporting problem rather than stale command output. Reports must be downgraded and READY/“no known functional RTL issue” removed until behavior and evidence agree.
