## Architecture and scope

- Single-module synchronous reconstruction, `design/intel_4002/src/intel_4002.sv`:
  320 bits of storage (4 registers x 16 main-memory characters x 4 bits +
  4 registers x 4 status characters x 4 bits) plus a 4-bit WMP output latch.
- 8-period instruction cycle (A1 A2 A3 M1 M2 X1 X2 X3) tracked from SYNC;
  command decode by listening at M1/M2; SRC select code latched at X2
  (chip number + register) and X3 (character); writes commit at the edge
  ending X3; reads drive during X2/X3 with an explicit `data_oe` — the exact
  protocol of the repository's verified `intel_4004` core.
- Chip selection: bank line (`cm_ram_i`) AND chip-number match; the number
  is formed by the `Variant1` metal-option parameter (4002-1 answers chip
  numbers 0/1, 4002-2 answers 2/3) and the `po_i` strap pin. WRR/WPM/RDR
  decodes are excluded as ROM-side operations.
- Reconstruction decisions (dynamic array and refresh out of scope, static
  storage, synchronous reset clearing everything in one edge, electrical
  behavior excluded) are enumerated in spec sections 9 and 11 with sources.

## Engineering notes

- The cover task is the one mode SymbiYosys cannot run with ABC
  (`Invalid engine 'abc' for cover mode`), and the image's only SMT solver,
  z3 4.8.12, does not converge on the natural encoding of this design: with
  the main/status arrays as SMT arrays, `smtbmc --unroll z3` stalled for
  hours at cover steps 7-9 (the first session's build never passed step 9).
  Experiments that failed or were too slow: incremental (non-unrolled) z3;
  `--nomem`; `--stbv`; plain `--syn` without `memory_map` was fast early
  but unproven at depth. The winning combination — mapping memories to
  flip-flops in the cover script plus removing the array mux from the cover
  query cone — brought 37/37 covers to PASS in about 90 seconds. The bmc
  and prove tasks were left untouched (ABC maps memories internally and
  already converged; pdr proved the full state equality unbounded in 56 s).
- Windows/Docker operational quirk: deleting `work/formal/*_console.log`
  while a killed container still holds the file leaves the name in a
  pending-delete state; subsequent in-container creates of that exact name
  fail with ENOENT (which masqueraded as a script failure once). Creating
  the file from the host clears it.
- Precedent from the intel_8259 build (scripted-stimulus cover environment)
  was considered but became unnecessary once the array representation was
  fixed.

## Historical record

The chip README and design index record **1971**, the year the MCS-4 family
was announced: the Intel advertisement in the November 15, 1971 issue of
*Electronic News*, which industry history treats as the announcement of the
first commercial microprocessor set. The year is not in dispute; the
November 15 date is specifically the advertisement's publication date, and
that framing is retained rather than guessing at a different day. The 4002's
two metal options (4002-1/4002-2 chip-number ranges) and the four-line
CM-RAM bank architecture are sourced from the November 1971 MCS-4 data
sheet scan; the programming model (SRC select-code fields, command set,
WMP port, RESET behavior) from the February 1973 MCS-4 Users Manual scan.
All source content is summarized and rephrased.
