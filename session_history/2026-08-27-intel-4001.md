# Session History: Intel 4001 Implementation and Verification

**Work date:** 2026-08-27 UTC
**Capture timestamp:** 2026-08-27 (written at session end)

## Goal

Build the Intel 4001 — the MCS-4 family's 2048-bit (256 x 8)
mask-programmable ROM combined with a 4-bit I/O port — as a complete
historical chip design under `design/intel_4001/`, with a sourced
specification, implementation/formal/test plans, synthesizable
SystemVerilog RTL, formal proofs, a direct self-checking testbench,
synthesis, reports, design-index integration, and a pull request. The bus
protocol is timed to interoperate directly with the verified
`intel_4004` reconstruction on branch `design/add-intel-4004`.

## Architecture and scope

- Single module `design/intel_4001/src/intel_4001.sv`: a synchronous
  reconstruction of the 4001 running from the CPU's 8-period instruction
  cycle (A1 A2 A3 M1 M2 X1 X2 X3) with a phase counter that re-locks to the
  CPU's SYNC pulse every cycle.
- Program fetch: word address latched low nibble first (A1), high nibble
  second (A2); chip number compared at A3 under CM-ROM; the selected chip
  drives ROM word bits [7:4] at M1 and [3:0] at M2.
- ROM-port I/O: on-chip snoop of every fetched OPR/OPA so all chips hear
  SRC (0010 RRR1), WRR (1110 0010), and RDR (1110 1010); SRC's X2 nibble
  latches the ROM-port select register (X3 ignored); selected WRR latches
  the bus nibble at the edge ending X3; selected RDR drives
  `(IO_DIR & latch) | (~IO_DIR & port_i)` during X2 and X3.
- Mask options as parameters: `CHIP_NO` (chip number), `IO_DIR` (per-pin
  direction), `ROM_INIT` (packed 2048-bit contents; under `FORMAL` it
  becomes an `anyconst` free constant so proofs cover every mask).
- Historical RESET and CL pins modeled as synchronous active-low `rst_n`
  (clears the sequencer/selection flip-flops, inhibits bus output) and
  `clr_n` (clears only the I/O output latch), per the manual's split of
  the two pins' jobs; `port_q` is deliberately not reset by `rst_n`.
- Out of scope: electrical behavior, the dynamic refreshed ROM array,
  per-pin inversion/pull-up mask options, WPM participation (the real part
  has none).

## Key decisions

- **Chip number on A3, not A1.** The task brief suggested the CPU sends the
  chip number during A1; the verified `intel_4004` RTL and MAME's
  `mcs40.cpp` both show the 12-bit address sent low nibble first
  (`addr[3:0]` at A1, `[7:4]` at A2, `[11:8]` at A3), so the chip number is
  the A3 nibble. The MCS-4 Users Manual's wording ("8-bit address during A1
  and A2 ... chip number together with CM-ROM during A3") agrees. The
  discrepancy is documented in the spec and final report.
- **WRR latched at end of X3, RDR driven through X2 and X3.** The manual
  places both events at X2; the companion CPU holds WRR data across X2/X3
  and samples reads at the end of X3, so the implemented windows are the
  compatible superset of both contracts.
- **SRC capture qualified by the snooped opcode, not CM-ROM**, because the
  companion CPU asserts CM-RAM (bank-decoded), not CM-ROM, at SRC X2/X3;
  captured value and X3-ignored semantics match the manual either way.
- **ROM contents as a packed parameter** (word(a) = (37a+61) mod 256
  default, a fixed bijection so every address is distinguishable in
  verification); `$readmemh` avoided so the same construct synthesizes and
  formally abstracts cleanly.

## Implementation and verification

- Direct (no-UVM) testbench `tb/tb_intel_4001.sv`: the bench plays the 4004
  side with genuine 8-phase cycles; two `intel_4001` instances (chip 0 /
  default mask / all-output port; chip 1 / mask B / `IO_DIR`=0011) share
  the bus; an independently written golden model decodes instructions from
  the observed bus and scoreboard-compares pins and internal state every
  period; directed scenarios D1-D15 plus 1,500 fixed-seed randomized ops.
- Formal `formal/intel_4001.sby` with tasks bmc (`abc bmc3`), prove
  (`abc pdr`), cover (`smtbmc --unroll z3`); immediate assertions only
  (Yosys rejects concurrent SVA); properties assume only a well-formed
  4004-style bus master with free `rst_n`/`clr_n` after the initial reset.
- Fail-fast scripts; `run_sim.sh` greps the log for `TEST PASSED` and
  exits nonzero on failure (xezim's exit status alone is not trusted).

## Issues found and fixed

- **Formal `s7_capture` bug (BMC FAIL at frame 10).** The WRR-latch
  assertion did not exclude CL low at the same edge; with `clr_n` free, BMC
  produced a counterexample where CL clears the I/O latch during a selected
  WRR's X3 — which is the correct RTL behavior (the real CL pin
  asynchronously clears the I/O flip-flops, dominating a simultaneous
  write). Fixed the property antecedent (requires `clr_n` high); the
  exhaustive triple CL-clears / WRR-writes / hold is covered by
  `s10_clear` / `s7_capture` / `s7_only_wrr`. Added directed test D15
  (CL through a complete WRR cycle) to the testbench for the same
  scenario. Debugging note: `abc bmc3` could not dump a trace because the
  image has no `yices` and the `aigsmt z3` witness conversion hits a
  yosys-smtbmc assertion; re-running the failing proof with engine
  `smtbmc z3` produced the VCD that pinpointed the case in minutes.
- **Unreachable cover goal `c29_reset_midcycle`.** The goal demanded the
  reset state one edge after `rst_n` deassertion, but synchronous reset
  takes effect one edge after the `rst_n`-low period (the chip first
  completes the period in progress) — the same latency trap the 4003
  build reported. Rewrote the goal to the reachable semantics.
