## Architecture and scope

- Implemented a single-clock functional reconstruction of the 8251A programming
  model as one module, `design/intel_8251/src/intel_8251.sv` (695 lines, no
  parameters, one `always_ff`).
- Implemented the four-state programming pointer (mode instruction, sync
  character 1, sync character 2, command instruction), asynchronous framing with
  5 to 8 data bits, optional odd or even parity and 1, 1.5, or 2 stop bits at 1x,
  16x, or 64x baud division, synchronous framing with contiguous characters,
  single or double sync character, internal or external sync detection, hunt
  restart, automatic sync-character fill on underrun, double-buffered transmit
  and receive datapaths, the `TxRDY`/`TxEMPTY`/`RxRDY` handshake, the readable
  status byte, parity/overrun/framing error flags with software error reset,
  break transmission and detection, modem control (`DTR`, `RTS`, `DSR`, `CTS`),
  and the software internal reset.
- Modeled the free-running `TxC` and `RxC` baud clocks as `txc_tick` and
  `rxc_tick`, single-cycle enable pulses, so the core stays single-clock and
  synthesizable. Documented this as a deliberate deviation.
- Exposed the shared CPU data bus and the shared `SYNDET`/`BD` pin as separate
  input, output, and output-enable signals; no tristate driver appears in the
  RTL.
- Added an active-low synchronous `rst_n` to establish a defined un-programmed
  state; documented that the historical part derives internal timing from a
  `CLK` pin and has no register-model reset beyond `RESET`.
- Excluded pin-level and electrical behavior, package behavior, metastability and
  clock-domain crossing between the core clock and the baud clocks, baud-rate
  generation, the RS-232 line interface, and original-8251 command-timing
  restrictions.

## Implementation and verification

- Added `design/intel_8251/tb/tb_intel_8251.sv` (1496 lines) with two
  independent checking mechanisms: a lockstep reference model whose right-hand
  sides all read a previous-state snapshot, compared against the complete output
  interface every sampled cycle; and a wire-level serial monitor and driver
  written from the frame definition in the specification, which decode the frames
  the transmitter emits and construct frames on `RxD` including injected parity
  and stop-bit defects.
- Added fourteen directed phases plus a fixed-seed 2,048-operation pseudorandom
  regression (`0x8251`), with minimum-count coverage assertions so a truncated
  run fails rather than passing.
- Added `design/intel_8251/formal/intel_8251_props.sv` (344 lines): combinational
  re-derivation and equality of all ten outputs, structural safety, synchronous
  reset priority for both hardware and internal reset, programming-pointer
  transitions, register-write retention, error-flag reset and stickiness,
  transmit and receive buffer fill provenance, the status-read sync-flag rule,
  and state-space invariants bounding both phase machines and all counters.
  Reset is assumed only in the initial formal cycle.
- Added `design/intel_8251/formal/intel_8251_cover.sv` (116 lines) with fifteen
  reachability covers over a free environment.
- Added the six fail-fast `#!/bin/sh` scripts, the chip README, specification,
  implementation plan, test plan, formal plan, coverage report, final report, and
  the sourced `design/README.md` index entry.

## Engineering notes

- Synchronous characters must be contiguous, so character launch is a single
  combinational condition shared by the idle state and by the boundary that ends
  the previous character. Routing the reload through the idle state instead would
  have inserted a one-bit gap between synchronous characters.
- The sync-hunt window originally extracted the previous character with a
  variable indexed part select. Verilator requires the index to be exactly
  `ceil(log2(width))` bits wide, but at that width Yosys treats the
  possibly-out-of-range select as undefined and `aig` aborts with
  "Design contains 'x' or 'z' bits". Replacing the part select with a right shift
  and a 16-bit mask comparison satisfies both tools with no waiver.
- Three testbench expectations were wrong rather than the RTL, and each was
  corrected to match real device behavior instead of being relaxed:
  a frame with a low stop bit leaves `RxD` low past the sample point so the
  receiver legitimately re-triggers and desynchronizes (added an explicit
  resynchronization helper); at 1x division the start bit lasts a single baud
  enable so it must be sampled immediately after the queuing write; and
  synchronous underrun re-asserts every character time, so the transition must be
  polled rather than sampled at a fixed offset.
- A testbench baud-enable divider bug caused the first regression to run 400,000
  cycles and hit `--max-time`: the phase counter wrapped on `==` and so went dead
  whenever the divider shrank. Changed to `>=`.
- Unlike the 8259, the ABC and Z3 engines both converge quickly here without a
  scripted cover environment, so the cover harness leaves the CPU bus, `RxD`, the
  modem inputs, and the external sync input free and lets the solver find each
  witness. Two covers that the free pre-reset state could satisfy vacuously were
  qualified with `configured` and `$past(rst_n)`.
- The container image was updated during the session (Yosys moved from 0.46 to
  0.59, which changes the `stat` summary format). `run_synth.sh` accepts either
  format so the flow is not tied to one Yosys release.

## Historical record

The design index and chip README record **1975\*** as the earliest located dated
Intel documentation, not as a claim of an exact commercial launch date. The
device appears as the 8251 Programmable Communication Interface in Intel's
September 1975 *8080 Microcomputer Systems User's Manual* (bitsavers archive
item `98-153B ... 197509`). Dated Intel references for the later variants are
narrower and later: an industrial-grade `ID8251` in the March/April 1979 *Intel
Preview* and the 8251A in the May/June 1980 issue, neither of which is
necessarily an introduction date. Availability may have preceded or followed
those documents, so the uncertainty is retained rather than guessed. Technical
behavior is sourced from an Intel 8251A datasheet reproduction, cross-checked
against the NJIT EE395 8251A programming notes for the mode, command, and status
bit assignments.

One datasheet ambiguity is recorded rather than hidden: whether synchronous mode
with external sync detection still consumes the sync-character writes. The
specification states the reading implemented (it does consume them, and the
stored characters are then unused) so the choice can be reviewed.
