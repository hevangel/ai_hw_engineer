# Micral N virtual-platform specification

Primary source: [R2E Micral N User Manual, January 1974 scan](../../../references/MICRAL_N_Users_Manual_Jan74.pdf) and its [searchable Markdown transcription](reference/MICRAL_N_Users_Manual_Jan74.md). The computer was introduced in 1973; the January 1974 manual documents the architecture, not a precise first-shipment date.

The virtual platform connects the repository's Intel 8008 core to 16 KiB of byte memory, input groups, output latches, and a front panel. The memory is divided into 64 pages of 256 bytes, as R2E describes in chapter III. The model supports a configurable full-memory image and host writes. It marks page 0 and pages 0x38–0x3f read-only when ROM protection is enabled, matching the recovered machine's boot and monitor locations described by the [MO5 restoration](https://hxc2001.pages-perso.free.fr/micral-n/index.html). These physical ROM locations are a restored machine's configuration, not a universal Micral N layout; R2E explicitly allows card address assignment.

The 8008 uses separate memory and I/O transactions in this virtual platform. Input groups follow R2E section II.2.5.2: the accumulator precharges the byte index and `INP G` returns byte A[2:0] of group G. Group 0 is the ASR-33 teletype card (byte 0 = received data, byte 1 = status with bit 0 input-ready and bit 7 output-ready; `OUT 8` transmits). Group 5 byte 0 carries the panel input switch bank for the included MO5 exercise. Group 6 is the Pile card, a hardware byte LIFO the boot and monitor use for subroutine state: `OUT 30` pushes the accumulator, `INP 6` pops, and an empty Pile reads zero. All other groups and indexes return zero. Output ports 8–31 latch data for the panel. The final output port corresponds to R2E output address /17 — hexadecimal 0x17, decimal 23 — and controls the optical watchdog indicator. The exact watchdog data bit is not established by the OCR text, so the UI displays the whole output byte instead of inventing a bit interpretation.

A host memory write and a CPU write in the same clock never collide: the board holds the CPU's `ready` low for that cycle, stalling it until the host store lands, and the CPU re-drives its own write afterwards. Host writes ignore ROM protection, matching a programming panel's role.

The optional console presents AUTO, STEP, instruction/cycle step, TRAP address, SUBstitution data switches, INIT, 14 address lamps, eight data lamps, fetch/read/write/I/O lamps, and run/wait/stop state. The host backend applies STEP and TRAP at simulator cycles/instruction retirements (STEP bounds an instruction at 8 enabled clocks; TRAP compares the post-retirement PC). SUB replaces memory data during a read, which is also the manual's entry path for the monitor. INIT synchronously resets the CPU. R2E's section VI is the source for control meanings. While the panel is open, the browser poll is the clock source: each poll runs at most 1200 cycles, so execution speed follows the poll rate and stops when the tab is hidden — a different execution model from the Busicom bridge's background thread, and sufficient for a front-panel tool.

The platform ships the original firmware: [boot EPROM and MIC-01 monitor ROM recovered by the MO5/hxc2001 restoration](reference/micral_rom_recovery.md), with checksums, entry points, and the verified board behavior. `tb_monitor` boots the monitor through the manual's front-panel procedure (SUBstitute `44 30 3B` over the fetches at PC 0/1/2, manual II.3.1) and verifies the documented teletype protocol. The default image remains MO5's publicly available `8008-input-output.bin` demonstration.

ASSUMPTION: All bus handshakes take one simulator clock, rather than preserving original Pluribus electrical and timing details. This uses the synchronous interface defined in the 8008 design spec.

ASSUMPTION: Unconnected Micral input groups return zero; real installations used configurable coupler cards. Teletype serial timing is not modeled: the UART-style card transfers assembled bytes, the receiver reports ready whenever its FIFO is non-empty, and the transmitter is always ready. The monitor's software parity survives on the wire (CR prints as 0x8D).

ASSUMPTION: The Pile card is modeled as a 64-byte LIFO (OUT 30 pushes, INP group 6 pops, empty reads zero) — the semantics the recovered firmware demonstrably relies on when it builds its warm-restart vector from two Pile pops. Pile underflow beyond 64 entries saturates rather than wrapping. The graded interrupt controller, real-time clock card, and Canal card are not modeled; panel INIT resets the core, and the 8008's instruction-injection input remains available for future board-level interrupt modeling.
