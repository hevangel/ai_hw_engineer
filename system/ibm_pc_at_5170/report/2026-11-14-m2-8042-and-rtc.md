# M2: 8042 and MC146818 on the board — 2026-11-14

## Result

With the 8042 keyboard controller and the MC146818 clock on the board, the
unchanged IBM AT REV1 BIOS (01/10/84) runs 1,125,813 instructions of its
power-on self-test and stops at `F000:068B`, a write to port F1h at POST
checkpoint 12h. Port F1h is the math-coprocessor reset port; the BIOS
writes it just before it initializes the 8259 interrupt controllers. Neither
is on the board yet. M1 stopped after 30 instructions.

On the way the BIOS passes its own tests of the devices added here: the
CMOS shutdown-byte read/write test (checkpoint 02) and the 8042 test at
`F000:03A2`–`0422`.

## What changed on the board

- The board top composes the native 80286 itself instead of using the 286
  design's fixture wrapper, so it owns CPU reset, INTR and NMI.
- 8042 (U126) at the even addresses 060h–06Eh, running IBM's firmware
  1503033. P20 resets the 80286 only, P21 gates A20, P24 is the
  output-buffer-full line, port 1 reads the switches and jumpers, and the
  keyboard clock and data circuit is modeled with no keyboard attached.
- MC146818 (U117) behind ports 70h/71h, with the NMI-mask bit, starting
  from a documented configuration record (`tb/cmos_configured.hex`).
- Each connection is cited to the March 1984 Technical Reference logic
  diagrams (sheets 1, 3, 5, 13, 16, 17, 18, 22) in the
  [specification](../spec/spec.md), with assumptions AT7–AT12.
- The POST runner accepts a write to an empty expansion-slot address (100h
  and above) and counts it. The BIOS makes two: 3B8h and 3D8h.

## What the BIOS did with the new devices

- 8042: read status F0h at `F000:00DE` (system flag 0, so a cold boot).
  In its test it sent AAh and polled the status register until 55h came
  back (39,265 status reads without wait states), sent C0h and read the
  input port as FFh, then wrote command byte 5Dh with command 60h.
- MC146818: wrote 8Bh to port 70h and read register B at `F000:01AF`,
  (02h), wrote it back with the interrupt enables clear, read register C,
  then walked a one bit through shutdown byte 0Fh and cleared it, reading
  each value back: 21 address writes, 10 data writes and 11 data reads in
  all.

## How the new parts are checked

- **8042.** The runner logs every instruction the RTL 8042 retires, every
  host write and data-register read with its position in the 8042's
  instruction stream, and every byte the CPU read. `scripts/check_kbc_log.py`
  replays the accesses into the UPI-42 reference model (written from Intel's
  manual, not from the RTL) running the same firmware. The model must retire
  the same instruction addresses in the same order and give the same value
  for every CPU read. The two bus-timing scenarios poll the 8042 a different
  number of times and both match.
- **80286.** The Unicorn replay was extended to the string instructions,
  SGDT/SIDT/LGDT/LIDT and SMSW that the BIOS uses after `F000:03A2`. The
  286 design's two AT BIOS fixture regressions give identical traces before
  and after the change.
- **MC146818.** Verified in its own design
  ([report](../../../design/motorola_mc146818/report/final_report.md))
  against a reference model written from the Motorola data sheet, including
  a replay of this BIOS's port 70h/71h sequences.

## Findings

- **The BIOS needs the MC146818 before the 8042 test.** The earlier plan put
  CMOS in M3. The BIOS reads register B 40 instructions after its first 8042
  read and halts at `F000:01AD` if the shutdown-byte test fails.
- **M1 defect fixed.** The board's "undriven read" flag fired during the
  wait states of a DMA register read, before the device's data was due. It
  is now checked when the read completes. M1 did not reach a DMA read, so
  its result is unaffected.
- **Decode PROM contents are unpublished.** U115 (74S288, sheet 18) decodes
  060h–07Fh for the 8042, port B, the NMI mask and the MC146818 from XA4,
  XA0 and the read/write strobes. The address sets used are the smallest
  consistent with its drawn inputs and the documented ports (AT8, AT9).
- **Yosys rejects `parameter string`.** The ROM-file parameters of the 8042
  and the board are untyped.

## Limits

- No independent whole-machine comparison yet (86Box or PCjs port-80h
  sequence). The checks here are per device and per instruction.
- At system level the MC146818 is checked only by the BIOS's own tests
  passing; there is no replay of its accesses into its reference model.
- Not compared with Unicorn, because it models a later CPU: MSW bits 4–15
  returned by SMSW, and the unused sixth byte stored by SGDT/SIDT.
- The 8042's RC line and the A20 gate are wired but not exercised: the BIOS
  has not pulsed reset or closed A20 by `F000:068B`. An 80286 shutdown still
  stops the run; the board's shutdown-to-reset path is M3.
- The keyboard connector is empty. IRQ 1 and IRQ 8 are board outputs with
  nothing connected; NMI is not connected.
- Clocks are functional ratios, not IBM timing (AT1, AT12). The 8042 runs
  one machine cycle per 15 processor clocks.
