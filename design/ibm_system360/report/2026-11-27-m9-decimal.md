# IBM System/360 — M9: decimal conversions and arithmetic

Date: 2026-11-27
Scope: the shared S/360 engine, ninth increment (program issue
[#379](https://github.com/hevangel/ai_engineer/issues/379), shared-engine issue
[#384](https://github.com/hevangel/ai_engineer/issues/384)).
Author: coding agent working under `AGENTS.md`.

## 1. What this increment adds

Eleven instructions (A22-6821-7 pp. 31-32, 35-40), taking the implemented set
from 54 to 65 operations:

| Group | Instructions |
|---|---|
| Conversions | `PACK` (F2), `UNPK` (F3), `MVO` (F1) |
| Register/decimal bridge | `CVB` (4F), `CVD` (4E) |
| Decimal arithmetic | `ZAP` (F8), `CP` (F9), `AP` (FA), `SP` (FB), `MP` (FC), `DP` (FD) |

Semantics implemented from the manual:

| Item | Implementation |
|---|---|
| Field format | `n` bytes hold `2n-1` digits plus the sign nibble in the low nibble of the rightmost byte; byte `k >= 1` carries digit `2k` high and `2k-1` low |
| Codes | digits `0-9` valid; signs `A, C, E, F` plus and `B, D` minus; results use the preferred sign (`C`/`D` EBCDIC, `A`/`B` ASCII-8 by PSW bit 12) |
| Processing | right to left, one byte at a time, stores immediately after the source bytes are fetched (pp. 35-36), so overlapped operands produce the architectural result |
| Condition codes | `AP`/`SP`/`ZAP` 0/1/2/3; `CP` 0/1/2; `MP`/`DP`/conversions unchanged |
| Data exception (7) | invalid digit or sign codes in `AP`/`SP`/`CP`/`MP`/`DP` operands (`ZAP` checks operand 2 only), or a multiplicand without the required high-order zeros |
| Decimal overflow (10) | `AP`/`SP`/`ZAP` result does not fit the first-operand field; completed with the truncated low-order result and CC 3, interrupting only when program mask bit 37 is one |
| Decimal divide (11) | `DP` divisor zero or quotient does not fit the `L1-L2` byte quotient field; suppressed |
| `MP`/`DP` specification | second-operand length code `L2 > 7` or `L2 >= L1` raises code 6, suppressed |
| `CVB` | doubleword operand, address must have bits 2-0 zero; out-of-range results store the low 32 bits and raise fixed-point divide (code 9) |
| `CVD` | doubleword operand with the same alignment rule; sign is the preferred code |

Two pre-existing correctness issues were corrected while implementing this:

1. **SET PROGRAM MASK bit order (M2-era defect).** SPM maps register bits 2-3
   to the condition code (PSW bits 34-35) and bits 4-7 to the program mask
   (PSW bits 36-39) positionally (p. 72). The core stored both fields
   bit-reversed and gated fixed-point overflow on program-mask bit 39 instead
   of bit 36, so the mask installed via SPM disagreed with the mask installed
   via `LPSW` in the stored PSW word. Tests 3 and 7 of the M8 testbench
   encoded the reversed convention and were corrected; the stored old PSW in
   the overflow test changed from `0xB100010E` to `0xB800010E`.
2. **Character SS protection coverage (M8 gap).** The M8 increment checked
   the protection key of only the first byte of each SS field. A field of at
   most 256 bytes spans at most two 2 KiB blocks, so the core now checks both
   end bytes of every field, which is exact.

## 2. Results

### 2.1 Lint

`verilator --lint-only -Wall` on the RTL alone and on RTL plus testbench:
**0 warnings, 0 errors** (scripts/run_lint.sh).

### 2.2 Simulation

`tb_ibm_s360_cpu` reports `IBM S360 M9 CORE TESTS PASSED (269 checks)` —
174 checks from the M8 suite (two updated for the SPM correction) plus 95 new
checks across tests 27-38: PACK, UNPK (including ASCII-mode zone 0101), MVO in
place and into a longer field, ZAP with signs and masked overflow, AP
same-sign/different-sign/carry/masked overflow with positive and negative
true-sign results, SP with a negative operand, CP across signs, lengths and a
data exception, MP with algebraic sign, the `L2 >= L1` specification exception
and the missing-leading-zeros data exception, DP with quotient/remainder
fields, the dividend-sign remainder, division by zero and quotient overflow,
CVB (positive, negative, overflow to code 9, unaligned to code 6, invalid
digit to code 7), CVD (positive, negative, unaligned, zero), ASCII-mode CVD
sign 1010, and the decimal-overflow interruption with mask bit 37 set.

### 2.3 Formal

All eight SymbiYosys jobs **pass**: ALU and address bmc/cover, PSW
bmc/prove/cover, and the core BMC at depth 12 (≈ 740 s with the decimal
datapath in the proof cone — the properties observe stores and condition
codes). The add-type finalize and the `MP`/`DP` validation run one cycle
after their last data step so the observed flags are settled. Non-vacuity
for the decimal instructions is covered by the simulation tests above; the
core cover task remains out of the default budget as in M3-M8.

### 2.4 Differential oracle

`tools/oracle/run_diff.py` compares retired architectural state against the
independent Model 30 emulator (issue #383): **45/45 cases agree** — 21
directed cases (8 new: pack, unpk, mvo_shift, zap_cp, ap_sp, ap_overflow,
mp_dp, cvb_cvd) plus 24 randomised binary cases.

Two deviations of the *emulator* were identified against the manual while
building the suite and are recorded here so a future mismatch is not blamed
on the RTL:

- its MULTIPLY DECIMAL data check requires the multiplicand to be smaller by
  one digit than the manual's rule ("high-order zero digits for at least a
  field size that equals the multiplier field size", p. 38);
- its decimal-overflow-to-zero result stores a plus sign where p. 37 keeps
  the sign of the correct result.

The suite avoids both boundaries; the RTL follows the manual.

## 2.5 Defects found while writing the tests

1. **UNPK sign nibble.** The core first swapped the zoned byte 0 the same way
   as PACK, putting the sign in the low nibble. Zoned format carries the sign
   in the *zone* (high) position of the rightmost byte (Figure 9, p. 35); the
   independent emulator caught it (`mem[0x214]` `0x5C` vs `0xC5`). The oracle
   comparison is what makes this class of mistake visible at all.
2. **MP/DP validation timing.** The captured operand registers update at the
   same edge that the validation read them, so the check saw stale zeros and
   raised spurious data exceptions. The validation now runs one cycle after
   the capture completes.
3. **Compare/add finalize timing.** The condition code was computed in the
   same cycle as the last digit compare, reading flags before that compare's
   updates landed (a `-5` vs `-12` comparison reported the wrong direction).
   The finalize now runs one cycle later with settled flags.
4. **CVB digit 0 unchecked.** The operand validity loop started at digit 1,
   so an invalid low digit raised nothing.
5. **CVB divide flag sticky.** `dec_div9_q` was not cleared per instruction,
   so after one out-of-range CVB every later instruction re-raised code 9.
   It and `dec_decovf_q` are now cleared in the execute state.
6. **Testbench encoding defects** (mine, not the core's): SS length fields
   off by one in four tests, `B1`/`B2` bytes written where displacements
   belonged, a PSW bit-12 poke in the wrong word position, and two
   SystemVerilog `"a" + "b"` string additions that are numeric, not
   concatenation.
7. **Storage-key array had no reset.** The key array relied on simulator
   zero-init, so keys loaded by the M8 tests leaked into the M9 tests. The
   array keeps no architectural reset (power-up state only, pp. 68-70); the
   testbench now clears all 64 keys through the key port in `start_reset`.

## 3. Limits

- `ED`/`EDMK` and floating point remain unimplemented (they raise code 1).
- `SSK`/`ISK` do not exist; keys come from the test port (M8 limit).
- I/O and machine-check interruptions are still missing; external remains
  timer-only (issues #385/#386).
- Decimal instructions check protection and addressing on both end bytes of
  each field; per-byte protection inside a field is unnecessary for fields
  shorter than a block and is not modelled.
- `MP` partial products and the `DP` trial subtracts run in one combinational
  BCD ripple per digit; timing claims stay out of scope.
- The instruction-fetch protection bit is still not applied to instruction
  fetch (M8 limit).
