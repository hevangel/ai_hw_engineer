# IBM System/360 — M10: EDIT and EDIT AND MARK

Date: 2026-11-28
Scope: the shared S/360 engine, tenth increment (program issue
[#379](https://github.com/hevangel/ai_engineer/issues/379), shared-engine issue
[#384](https://github.com/hevangel/ai_engineer/issues/384)).
Author: coding agent working under `AGENTS.md`.

## 1. What this increment adds

Two instructions (A22-6821-7 pp. 58-60), taking the implemented set from 65
to 67 operations: `EDIT` (DE) and `EDIT AND MARK` (DF). With them the shared
engine covers every instruction group of the -7 manual except floating point
and the channel-I/O instructions.

| Item | Implementation |
|---|---|
| Format | SS with one length: the length bounds the *pattern*; the source is consumed digit by digit, one examination per selector or starter, without a length field |
| Fill character | the pattern's first byte, taken before its own editing action (p. 58) |
| Result characters | digit selector (20) / significance starter (21): zoned source digit (preferred zone by PSW bit 12) when the indicator is on or the digit is nonzero, else the fill; field separator (22): always the fill, indicator off; message bytes: unchanged when on, fill when off |
| Indicator | off at start, after a separator, and after a plus code (1010/1100/1110/1111) in an examined byte's low nibble; on when a starter sees a valid digit or a selector a nonzero digit unless that plus code applies; a minus code (1011/1101) leaves it (p. 58) |
| Condition code | 0 last field's digits all zero, 1 nonzero with the indicator on, 2 nonzero with the indicator off (pp. 58-59) |
| Source termination | a sign code in a fetched byte's high nibble ends the operation; the rest of the pattern is untouched; the instruction retires normally (p. 58) |
| EDMK marking | on each zoned-source-digit replacement with the indicator previously off, the result character's address goes into general register 1 bits 8-31 (p. 60) |
| Consumption checks | addressing and fetch protection are checked per consumed source byte; a violation raises code 5/4 mid-operation with earlier stores in place (deviation A-13) |

## 2. Results

### 2.1 Lint

`verilator --lint-only -Wall` on the RTL and on RTL plus testbench: **0
warnings, 0 errors**.

### 2.2 Simulation

`tb_ibm_s360_cpu` reports `IBM S360 M10 CORE TESTS PASSED (294 checks)` —
269 from the M9 suite plus 25 new across tests 39-44: EDIT of a positive
number with leading-zero suppression and CC 2, a negative number whose D
sign leaves the indicator on (CC 1), an all-zero field filled throughout
with CC 0, EDMK across two adjacent source fields with a field separator,
the second field's mark address in GR1 and CC 1, the p. 58 source
termination rule (a high-order sign code ends the edit, remaining pattern
untouched, no interruption), and the ASCII-8 zone 0101 under PSW bit 12.

Two testbench defects were found and fixed while writing these tests: two
source pokes used SystemVerilog `"a" + "b"` string addition (numeric, not
concatenation — the same mistake as M9's, caught because the EDIT result
showed the machine correctly editing garbage), and the EDMK case forgot
that its fill character is the pattern's first byte `0x20`, so the fill
positions legitimately keep `20`.

### 2.3 Formal

All eight SymbiYosys jobs pass, including the core BMC at depth 12; the
EDIT consumed-byte raise is part of the observed interruption contract.

### 2.4 Differential oracle

`tools/oracle/run_diff.py`: **50/50 cases agree** with the independent
emulator — 26 directed cases (5 new: `ed_basic`, `ed_negative`, `ed_zero`,
`edmk_fields`, `edmk_starter`) plus 24 randomised binary cases.

One deviation of the *emulator* is recorded (A-12): under z/Architecture
rules an invalid high-order nibble raises data exception code 7, and the
emulator implements that; A22-6821-7 p. 58 instead *terminates* the
operation when a sign code is detected in the high-order positions. The RTL
follows the -7 manual (test 43 pins this); the oracle case set keeps
selectors equal to digits so the boundary is never exercised in a
comparison, and a future mismatch there must not be blamed on the RTL.

## 3. Limits

- Floating point remains unimplemented (raises code 1) — the last
  instruction gap outside channel I/O.
- `SSK`/`ISK`, instruction-fetch protection, I/O and machine-check
  interruptions are still missing (M8/M9 limits).
- EDIT protection/addressing violations on consumed source bytes leave
  partial stores (A-13); the manual calls the terminated results
  unpredictable.
- The data exception in the `ED`/`EDMK` instruction-summary entry is not
  raised by this core (A-12).
