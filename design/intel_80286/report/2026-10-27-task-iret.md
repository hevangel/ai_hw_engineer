## Scope implemented

Intel's [80286 and 80287 Programmer's Reference Manual, order 210498-005,
§§8.3–8.4 and Table 8-2](https://bitsavers.org/components/intel/80286/210498-005_80286_and_80287_Programmers_Reference_Manual_1987.pdf)
defines IRET with NT set as a task return through the current TSS backlink. The
286 requires the backlink selector to identify a busy, present GDT TSS. The
return saves the active task's continuation, clears that task's busy bit,
switches to the backlink task without nesting, and resumes after the IRET if
the outgoing task is invoked again.

The core now recognizes protected IRET with NT set before reading a stack
frame. It reads the backlink, validates a busy present GDT 286 TSS and current
TR descriptor, saves the active task's dynamic TSS words with its post-IRET IP
and NT cleared, clears the active TSS busy bit, and loads the backlink task.
The existing staged task-entry path validates a null LDTR and SS/CS/DS/ES,
then atomically publishes the restored task state. The returning task's TSS
remains available; the backlink task remains busy. TS remains set by the task
switch. Non-null LDTR and architectural exception delivery for invalid
backlinks/TSS/segments remain outside this checkpoint.

## Directed evidence

The `--iopl-controls` fixture enters a #DF task through a task gate. The
handler executes IRET; the core restores the interrupted CPL3 task, which
re-executes the faulting HLT and enters the same #DF task again. The test
observes fetches at the handler IRET, the original faulting task, and the
handler's saved post-IRET successor. It also checks the outgoing task TSS
contains `IP=0301`, `FLAGS=0002` (NT cleared), and `SP=007E`; the TSS busy
access byte transitions from `83` to `81` and back to `83`; both zero #DF
error words are pushed at the expected addresses; and the re-entered handler
halts exactly at `0030:0302`. Immediate and stalled READY modes both pass.

## Limits and next work

This verifies one valid #DF task entry and return with a null LDTR. Invalid
backlink selector/type/presence/limit cases and incoming descriptor faults
still stop diagnostically rather than following the 286 exception table.
There are no task-switch reset cuts or connected-core properties for this new
path. The older `_21` cover and PDR jobs remain active on prior snapshots; at
the last status read, cover was waiting at step 35 and PDR had proved 366
outputs at 11:33:15 UTC. No overlapping core proof was started.

Next implement architectural #TS/#NP/#GP priority for invalid task-return and
incoming-segment states, then cover additional #DF causes, shutdown, reset
behavior and task-switch formal properties. Full 80286 acceptance remains
open.
