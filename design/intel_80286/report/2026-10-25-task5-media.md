## Historical context and harness lead

The OS/2 Museum's history says Microsoft began shipping SDK 1.00 in May 1987;
the SDK contained a pre-release OS/2 build, development tools, examples, and
documentation. This is not the final retail OS/2 1.0 release. The same source
explains that the SDK was intended for PC/AT-class 286 systems. See [OS/2
Beginnings](https://www.os2museum.com/wp/os2-history/os2-beginnings/).

PCjs publishes an IBM PC AT configuration and states that its PCx86 emulator
can run OS/2 1.0 with 80286 protected mode. The PCjs author also documents
known OS/2 problems, including installation hangs and possible lost
interrupts. This makes PCjs useful as an independent behavioral comparison
candidate, not as a normative 286 specification or a sign-off oracle. See
[PCjs: OS/2 1.0](https://www.pcjs.org/blog/2014/12/04/) and [PCjs: IBM PC AT
(Model 5170)](https://www.pcjs.org/machines/pcx86/ibm/5170/).

The local PCjs source clone and its machine configurations are under ignored
`scratchpad/pcjs/`. The `diskimage` CLI dependency was resolved locally, and
the headless run now loads the SDK program disk with `--diskette` plus a local
hard disk with `--disk`. It prints the OS/2 Version 10.0, Revision 3.42.1.1
banner, then the AT BIOS reports `1782-Disk Controller Failure`. Pressing F1
prints the banner again but does not produce a command-shell prompt. A
scheduled CPGREP command was injected after the prompt with no program output;
there is no evidence that CPGREP executed. No local media was sent to a remote
emulator, and no independent instruction trace has been recorded.

## Next evidence steps

1. Determine whether the PCjs BIOS 1782 error can be cleared with a valid AT
   hard-disk/controller configuration and reach an interactive OS/2 shell. If
   this PCjs build remains stuck after the kernel banner, switch to another
   local independent 286 environment or a hardware/recovered execution trace.
2. Once the shell works, run unchanged CPGREP against a pinned fixture and save
   the exact invocation, program output, and hashes for inputs and output.
3. Capture an instruction/exception trace from a 286-specific external
   emulator or hardware artifact for the exercised protected-mode behavior.
   Keep the CPGREP workload and the focused #GP fixture distinct: OS/2 software
   provides real protected-mode execution but does not itself close the
   Task 4 exception oracle requirement.
4. Add the harness and expected output to the design regression only after
   the emulator run and external behavior have been independently reviewed.
