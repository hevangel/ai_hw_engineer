# 80286 processor-extension data channel

Intel's [80286 Hardware Reference Manual, 210760-002, chapter 6](https://www.bitsavers.org/components/intel/80286/210760-002_80286_Hardware_Reference_Manual_1987.pdf) specifies the channel's transfer order: memory is read before the extension write, while the extension is read before memory is written. An aligned word uses one memory and one I/O operation; an odd word uses two memory operations. PEACK# is active during the first operation. A complete transfer is indivisible, and its priority relative to HOLD, LOCK and other operations is specified there. The [80287 data sheet](https://bitsavers.org/components/intel/_dataSheets/80287_Data_Sheet_Feb83.pdf) specifies active-high PEREQ and active-low PEACK#.

`intel_80286_pedc` is a **standalone transaction engine under development**. A future CPU controller must supply a valid physical address, direction and word count after architectural access validation, and must give the engine exclusive ownership for each complete word. `grant_i` and `ready_i` qualify a beat; the owner must retain grant across a word and prevent HOLD/other owners from interleaving beats. The engine does not generate physical bus status timing or establish operand length, descriptor permissions, fault priority, LOCK#, or CPU retirement. It has no connection to the core or native wrapper yet.

ASSUMPTION A26: the engine requires a sampled low PEREQ between accepted requests. The data sheet says the extension withdraws PEREQ on PEACK# or the data transfer, but whether the CPU must observe an intervening low on its sampling clock is not established. Validate A26 against a real 80287 or an independent pin trace before sign-off. The BUSY start/stop sampling and the mapping of this abstract PEACK# interval to physical pins also need independent timing validation. `words_i` bounds the configured transfer; exhaustion or a BUSY fall after BUSY has been observed terminates the channel. Fault and reset handling across the connected CPU remain unverified.
