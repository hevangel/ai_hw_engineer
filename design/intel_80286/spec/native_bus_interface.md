# Intel 80286 native local-bus interface

Update: the [D8 physical-command report](../report/2026-10-30-d8-physical-command.md) documents the later register-form command sequence and a connected native word-bus check. The operand data channel remains unimplemented.

Status: source-backed contract for the native CPU-pin layer. A parameterized
core beat interface, CPU-pin cycle controller, separate local 82288 model, and
connected pin-level CPU wrapper pass directed simulation. The wrapper accepts
processor-rate `clk_i` and external 2x `clk_2x_i`; the connected test driver now
generates those clocks at the documented 2:1 frequency ratio with a selected
digital phase. LOCK-prefix transfers, memory XCHG and 82288 strobes are
exercised through the connected path. Generic synthesis does not qualify a
physical device. See the native-clock, native-bus, native-CPU and 82288 reports
for component evidence and limits.

## Reference and boundary

The primary hardware reference is Intel, *80286 Hardware Reference Manual*,
order 210760-002 (1987), especially Chapter 3: Table 3-1 and Figures 3-5
through 3-16, plus the reset timing discussion on printed pages 3-41–3-42.
Use the [archived Intel manual](https://www.bitsavers.org/components/intel/80286/210760-002_80286_Hardware_Reference_Manual_1987.pdf)
and the [text-readable copy](https://manuals.plus/m/d3ece037a200b17ef32d78a055d0d96c3e47474d755d94569b9576a9a68c6915).
Use Intel, *80286 and 80287 Programmer's Reference Manual*, order 210498-005,
for instruction-controlled LOCK and coprocessor behavior.

This contract describes the CPU's local-bus pins. The CPU drives the address,
data, status, arbitration, lock, interrupt and processor-extension signals.
ALE, MRDC, MWTC, IORC, IOWC, INTA and MCE are generated by the 82288 Bus
Controller from the CPU signals; they are system-interface outputs, not 80286
CPU pins. A later board-level model may add the 82288 behavior as a separate
component. Do not connect a CPU status signal directly to an 82288 command
strobe without modeling that decode and timing.

## CPU signal set

The native layer must model these signal groups with source-defined polarity:

| Direction | Signals | Contract |
|---|---|---|
| CPU to system | `A23:A0`, `BHE#`, `COD/INTA`, `M/IO`, `S1`, `S0`, `LOCK#` | 24-bit physical address; byte-lane selection; four unlatched bus-status signals; bus lock. Status is valid for the first half of the bus cycle. |
| Bidirectional | `D15:D0` | 16-bit data bus; model read, write and released/high-impedance phases explicitly. |
| System to CPU | `CLK`, `RESET`, `READY#`, `HOLD`, `INTR`, `NMI`, `PEREQ`, `BUSY`, `ERROR#` | Clock/reset, wait termination, bus request, interrupts and processor-extension requests/status. |
| CPU to system | `HLDA`, `PEACK#` | Bus-hold acknowledgement and processor-extension data-transfer acknowledgement. |

`RESET` is active high. `READY#` is active low: low terminates the active
perform-command state; high repeats that state. `HOLD` and `INTR` are active
high. `NMI` is an active-high edge-triggered request. Processor-extension
`PEREQ` and `BUSY` are active high; `ERROR#` and `PEACK#` are active low.

The CPU's external `CLK` is divided internally by two. The bus states below
are each one processor-clock long, not one external CLK period. Keep the clock
relationship explicit in the RTL and testbench; do not silently treat one
simulation edge as one historical CPU clock without selecting and documenting
that timing convention. The connected test's clock driver holds `clk_i` high
for one external CLK period and low for the next, so one full processor-clock
period spans two external periods. Its phase is a deterministic digital test
choice, not an 82C284 reset-phase or electrical-timing claim.

## Address and data lanes

The address bus is 24 bits and the data bus is 16 bits. `A0` and active-low
`BHE#` select byte lanes:

| `BHE#` | `A0` | Transfer |
|---:|---:|---|
| 0 | 0 | word, both lanes |
| 0 | 1 | odd-address byte on `D15:D8` |
| 1 | 0 | even-address byte on `D7:D0` |
| 1 | 1 | reserved |

An odd-addressed word is two bus cycles: first the low byte on the upper lane
at the odd address, then the high byte on the lower lane at the next even
address. An even-addressed word uses both lanes in one bus cycle. The bus layer
must not collapse an odd word into a single aligned transfer.

Real-address mode uses a 20-bit physical address; system memory decode ignores
`A23:A20` in that mode. Protected mode uses all 24 physical address bits.
Memory and I/O are separate spaces. I/O addresses are port addresses, and the
status encoding identifies I/O cycles independently from memory cycles.

## Bus status and cycle classes

Decode the complete tuple `{COD/INTA, M/IO, S1, S0}`. Implement only the
documented rows in Intel Table 3-1; reserved combinations must not become a
memory or I/O transfer. The documented classes are:

| Class | `COD/INTA` | `M/IO` | `S1` | `S0` |
|---|---:|---:|---:|---:|
| Interrupt acknowledge | 0 | 0 | 0 | 0 |
| Halt or shutdown | 0 | 1 | 0 | 0 |
| Memory data read | 0 | 1 | 0 | 1 |
| Memory data write | 0 | 1 | 1 | 0 |
| I/O read | 1 | 0 | 0 | 1 |
| I/O write | 1 | 0 | 1 | 0 |
| Memory instruction read | 1 | 1 | 0 | 1 |

For halt/shutdown status, address pin `A1` distinguishes the operation:
`A1=1` is HALT; `A1=0` is shutdown. This status cycle does not perform a
memory or I/O data transfer. Keep `A1` observable in this cycle even when the
functional transaction interface has no outstanding byte request.

The status signals are not latched. They are meaningful only in their
documented status window; register or scoreboarding logic must sample them in
that window rather than infer a cycle class from a later address or data phase.

## Bus states, waits, and sequencing

The local bus uses `Ti` (idle), `Ts` (send status), `Tc` (perform command) and
`Th` (hold). A bus cycle begins with `Ts`, followed by one or more `Tc` states.
`READY#` low completes the active `Tc`; `READY#` high repeats `Tc` without
changing the active address, status class, lane selection or write data. With
READY asserted, the bus can transition directly from one operation to the
next `Ts`, or pass through `Ti`. The CPU's pipelined fetch and data operations
may therefore produce back-to-back cycles.

An 82288 decodes CPU status and produces ALE and the command/data-buffer
strobes. For read cycles, sample input data when the active `Tc` terminates.
For writes, hold output data through the completion edge and through any
repeated `Tc` states. These rules apply separately to memory, I/O and interrupt
acknowledge timing; the controller's output strobes have their own timing in
Intel Figures 3-14 through 3-16.

The 82288 command decoder uses `M/IO`, `S1` and `S0`; it does not need
`COD/INTA` to distinguish memory and I/O commands. Address-decode logic may
still use `COD/INTA` to route an interrupt-acknowledge cycle because the CPU
address bus is not a normal memory address during INTA. The timing reference
for any modeled controller must use the external `CLK`, whose frequency is
twice the processor clock. In the Intel M82C288 reference, each `Ti`, `Ts` and
`Tc` state is two external CLK periods, ALE is active in the second half of
`Ts` and inactive at its end, and active-low READY is sampled at the end of
each `Tc`. This is a cycle-level model contract, not analog timing evidence.

`intel_80286_82288` implements the initial single-local-bus, non-MULTIBUS
profile. It advances on falling edges of the separately supplied external
`clk_2x_i`: one edge spans one external CLK period, and two periods form each
`Ts` or `Tc`. The CPU wrapper leaves clock division and phase generation to its
caller. It connects CPU status-valid plus `{M/IO,S1,S0}` to the controller,
and routes ALE, DEN, DT/R, active-low memory/I/O/INTA strobes and MCE to its
outputs. This is a digital cycle model; it does not model pin delay, setup/hold,
bus capacitance, speed-grade limits or the CPU RESET deassertion delay.

The Intel *80286 Hardware Reference Manual*, order 210760-002, has a
contradictory sentence about `CENL`: its diagram straps the always-selected
local controller high, but the text says sampled-high causes the controller
to ignore a cycle. Intel's original HMOS M82288 datasheet resolves this: CENL
is active HIGH, latched at the start of a bus cycle, and sampled HIGH at the
end of `Ts` enables the controller. Sampled LOW suppresses commands and DEN.
The later M82C288 datasheet is compatible and confirms the same polarity.
Model `CENL=1` as selected. In local mode, `CEN` asynchronously gates
commands and DEN; `CMDLY=1` delays command activation, and READY is sampled at
the end of each `Tc`. `ALE` is active in the second phase of `Ts`, except on
halt. For INTA, MCE is active with ALE and remains active for one external CLK
period after ALE falls; it is not gated by controller-enable inputs. In the
modeled local profile, write DEN may be prepared in phase two of `Ts`, before
the end-of-`Ts` CENL decision suppresses DEN for an unselected cycle. See the
[original-source reconciliation and model profile](../report/2026-10-28-82288-cenl-source-conflict.md).

## Bus ownership and LOCK

`HOLD` requests local-bus ownership. When granted, `HLDA` asserts and the CPU
releases address, data, status and other bus-driver outputs to high impedance.
If HOLD is recognized during `Tc`, the CPU passes through `Ti` before entering
`Th`. Ownership returns after HOLD is removed. Model high impedance with
explicit output-enable state; a two-state FPGA output value is not proof of a
released physical bus. `HLDA` itself remains driven.

`LOCK#` is active low and prevents another bus master from acquiring the
protected resource for the documented operation. The CPU asserts it for the
LOCK prefix and for automatic hardware cases including XCHG memory operations,
interrupt acknowledge sequences, and selected descriptor-table accesses.
The core now decodes explicit LOCK-prefixed memory MOV, MOVS, INS, OUTS and
rotate-memory operations, and asserts automatic LOCK for memory XCHG. The
instruction manual's B-68 entry names MOVS/INS/OUTS; the hardware manual's
Table 3-5 also lists MOV and rotate-memory operations. Broader prefix legality,
LOCK-related privilege checks, descriptor-table locks and processor-extension
locks remain open. The active-low output stays asserted through operand
transfers and their internal gaps, including all iterations of a repeated
string operation, and is inactive during instruction fetch. Keep LOCK asserted
across both back-to-back INTA cycles. The pin-level test checks READY waits,
locked read/write gaps, repeated MOVS/INS/OUTS iterations, no HOLD grant while
locked, release after the operation and no LOCK during instruction fetch.

## Interrupt and processor-extension transfers

For a recognized `INTR`, execute two back-to-back interrupt-acknowledge bus
cycles. Lock the bus across the pair; the first cycle participates in
interrupt-controller cascade/freeze behavior and the second supplies the
8-bit vector. `NMI` supplies vector 2 internally and does not generate INTA
cycles. Preserve the distinct architectural event path and external bus path.

The Intel [80287 data sheet (February 1983)](https://bitsavers.org/components/intel/_dataSheets/80287_Data_Sheet_Feb83.pdf)
defines `BUSY` as an indication that the extension is executing and `ERROR`
as the unmasked-error indication. `PEREQ` is active high: the 80287 asserts it
when ready to transfer data, then withdraws it when the CPU acknowledges with
`PEACK#` or when the data transfer occurs, whichever happens first. The CPU's
active-low `PEACK#` input to the extension acknowledges PEREQ and can withdraw
the request when no more transfers are needed. The pin table and hardware
interface figures (PDF pages 2–4) define the sampled CPU status and shared
data-bus connection. The extension communication interface also uses I/O
addresses `00F8h`, `00FAh`, and `00FCh`: `NPS1` low with `NPS2` high selects the
80287, `CMD0` is connected to latched CPU `A1`, `CMD1` to latched `A2`, and
`NPRD`/`NPWR` enable data transfer direction. The entire `00F8h–00FFh` I/O
range is reserved for this interface. The interrupt table and discussion
(PDF page 8) assign vector 7 to ESC when MSW.EM or MSW.TS is set, and vector 16
to an unmasked extension error. Intel's [80286/80287 Programmer's Reference Manual,
§3.12.1](https://bitsavers.org/components/intel/80286/210498-005_80286_and_80287_Programmers_Reference_Manual_1987.pdf)
(printed page 3-30) says WAIT suspends until BUSY indicates completion and
describes ESC handing the instruction and location to the extension.

Intel 210760-002, *80286 Hardware Reference Manual*, Chapter 6, printed
pages 6-2–6-6, defines the CPU/extension transaction. The `BUSY` output is
connected directly to the CPU and is asserted high while the 80287 executes;
WAIT and most ESC instructions wait until it goes inactive. `ERROR#` may
assert before `BUSY` goes inactive, so the CPU reports vector 16 only after
that wait. On ESC, EM/TS context checks precede the BUSY wait.

After the check, the CPU issues one or more reserved-port I/O operations for
the ESC. The operations bypass I/O privilege checks and require no wait states.
If an operand transfer is needed, the CPU initializes its processor-extension
data channel with the address bounds and direction. The 80287 requests a
transfer by asserting `PEREQ`; the CPU acknowledges by asserting active-low
`PEACK#`, which is active during the first bus operation. A word operand uses
one I/O bus operation to the 80287 and one or two memory bus operations; an
odd-address word needs two memory cycles. Channel word transfers are
indivisible, outrank execution data and prefetch, wait behind an active LOCK
or the second half of another word, and remain below HOLD. Their bus-cycle
timing matches ordinary I/O and memory cycles. The 80287 datasheet's
data-transfer/data-channel waveforms (PDF page 19) give pin timing; its error
waveform (PDF page 20) gives ERROR#/BUSY ordering. The RTL does not yet
implement these operations or timing edges.

Intel 210760-002 Chapter 6 Figure 6-3 (printed page 6-6, PDF page 216) further
limits the request window: operand transfers may occur after ESC only while
BUSY is asserted, and no new channel request is accepted after BUSY falls until
the next ESC. A word transfer takes two bus cycles at an even address and
three at an odd address. This is enough to pin channel timing, but not the
missing per-ESC reserved-port command bytes or port order.

Intel AP-113, *Getting Started With the Numeric Data Processor* (1981),
[printed page 9](https://bitsavers.org/components/intel/appNotes/AP-113_Getting_Started_With_the_Numeric_Data_Processor_Feb81.pdf),
describes an 8087 connected to an 8086/88 host. Its S2:S0 bus-status and
QS1:QS0 queue protocol is not the 80286/80287 interface and is not used to
infer the 80287 ESC command sequence.

The current implementation covers a limited exception/wait slice. WAIT raises
vector 7 for TS, waits while active-high `BUSY` is asserted, and checks
active-low `ERROR#` after the extension becomes ready. ESC D8–DF decodes its
ModR/M byte, raises vector 7 for EM or TS, waits for BUSY to clear, and then
raises vector 16 for a prior unmasked error before any operand data read. A
normal ESC remains a development diagnostic. The native wrapper exposes
`BUSY` and `ERROR#`, but successful ESC command transfer,
`PEREQ`/`PEACK#` handshaking, reserved-port decode, extension data routing and transaction timing
are not implemented. Functional-core NMI/INTR selection during WAIT's BUSY
stall is covered in real mode and by 16 protected CPL1/CPL2 cases, with
saved-IP assumption A25 still open. Native WAIT pin timing, ESC interruption,
prefix legality, segment-fault priority and automatic LOCK remain open; this
slice does not establish the complete 80287 interface. See the
[WAIT interruptibility report](../report/2026-10-28-wait-interruptibility.md)
and the [protected WAIT report](../report/2026-10-28-protected-wait-interruption.md).

## Reset and shutdown

The board-level 82C284 reset input `RES` is active low. Intel 210760-002,
Chapter 3, printed pages 3-41–3-42, says to hold `RES` below 1.05 V for 5 ms
after VCC reaches 4.5 V, then keep it low for another 16 processor-clock
cycles. RESET also initializes the 80286's internal divide-by-two clock state;
the manual describes synchronizing PCLK at the first bus operation after
RESET.

Intel 210760-002 has inconsistent single-CPU edge wording: printed page 3-41
says the high-to-low transition of CPU `RESET` must be synchronized to system
`CLK`; pages 3-42–3-43 describe a one/two-`CLK` delay before the 82C284 drives
`RESET` high, say it attempts to synchronize the rising edge, and allow the
falling edge to be asynchronous when VCC/CLK are not valid. Figure 3-38 shows
the `RES` input and RESET output timing; the optional multi-processor
synchronizer in Figures 3-39 and 3-40 is a separate board circuit.

The Intersil June 2004 82C284 datasheet, printed page 4, specifies that active-
low `RES` is synchronized at the falling edge of `CLK`, with a one- or two-CLK
delay before it affects active-high `RESET`. It also says 80C286 and support-
component RESET inputs must remain high for at least 16 CLK periods. The
datasheet is an original Intersil document for its later CMOS 82C284 and names
the 80C286; it corroborates a digital reset path but does not establish
electrical limits or prove identical behavior for every Intel-manufactured
82C284. `intel_80286_82c284_reset` models the documented one/two-falling-edge
delay as a standalone digital slice. Its two settings pass a focused regression.
It is not connected to `intel_80286_native_cpu` and omits analog RES/VCC
qualification, the CLK/PCLK generator, and board timing. See the
[reset-source report](../report/2026-10-28-reset-source-audit.md).

`intel_80286_native_cpu` accepts an optional already-conditioned active-high
`reset_i` and an active-low 82C284 `res_n_i`. The integrated RES path samples
on `clk_2x_i` falling edges and defaults to the two-CLK delay; the parameter
also permits one CLK. `cpu_reset_o` is the active-high signal delivered to the
core, bus and 82288 controller. The conditioned input remains available for
systems that already contain an external reset circuit.

Both connected pin-test modes apply reset for at least 16 processor clocks,
check CPU bus and 82288 outputs remain idle, and verify the first fetch at
physical `FFFFF0h`. The separate reset-component test checks both one- and
two-CLK settings, transition polarity and edge, plus a 16-external-CLK RESET
hold. These digital checks do not model or qualify the 82C284 analog
`RES`/VCC interval, clock generation, oscillator, or PCLK phase adjustment.
The inspected reset pages do not substantiate the former claim of a fixed
38-external-CLK delay from RESET deassertion to the first bus cycle, so that
number is not a contract or test threshold. The first reset fetch must still
be checked at physical `FFFFF0h`, including the real-mode address-decode rule
for upper address bits. HALT and shutdown remain separate status outcomes,
decoded from status plus `A1` as above; RESET is the recovery path from
shutdown unless the documented NMI recovery path commits successfully.
See the [reset timing source audit](../report/2026-10-28-reset-source-audit.md)
for the page-specific source notes and connected-test evidence.

## Verification contract

Before this interface is called implemented, pin-level simulation must check:

1. Every documented status tuple and rejection of reserved tuples.
2. All four `A0`/`BHE#` combinations, byte-lane routing, even words, and odd
   words split into the documented two cycles.
3. Memory and I/O reads/writes, stable outputs through repeated READY waits,
   and the correct read-sampling/write-acceptance edge.
4. Back-to-back `Ts` cycles, `Ti` entry, and `Th` entry/release with output
   enables matching bus ownership.
5. LOCK-prefix and automatic-lock cases, including no HOLD grant while
   locked.
6. Both INTA cycles, lock coverage, first-cycle controller effects and
   second-cycle vector sampling; NMI with no INTA cycles.
7. HALT versus shutdown using `A1`, no accidental data request, shutdown
   persistence and RESET recovery.
8. The standalone 82C284 reset slice samples RES on falling CLK and checks
   both documented one- and two-CLK delays plus the 16-CLK RESET hold. The
   connected CPU test separately checks the conditioned RESET pulse, bus quiet
   during reset and first fetch at each selected speed-grade timing profile.
9. PEREQ/PEACK, BUSY and ERROR interactions using an independently sourced
   80287 interface contract.
10. The 82288 profile's memory/I/O/INTA strobe decode, active-low polarity,
    CENL selection, asynchronous CEN gate, CMDLY delay, write DEN preparation,
    READY waits, direct back-to-back cycles, halt ALE suppression, and MCE's
    one-CLK extension beyond ALE during INTA.

Bind each result to exact RTL, testbench, timing-profile and reference hashes.
Simulation establishes the modeled protocol only; electrical timing, analog
behavior, speed-grade limits and physical qualification require separate
evidence.

## Open design decisions

- Select the supported 80286 speed grades and external clock timing profiles.
- Supply and phase-align the processor-rate and external 2x clocks in a board
  or system wrapper; the native CPU wrapper accepts both clocks explicitly.
  The connected test selects the documented nominal 2:1 frequency relation
  and a repeatable phase, but does not implement the board clock source.
- Implement and source the MULTIBUS (`MB=1`) timing profile if that mode is
  required; the current controller supports local non-MULTIBUS operation only.
- Define four-state or explicit output-enable modeling for released pins.
- Integrate the source-backed digital RES synchronizer with a board-level
  wrapper only after selecting the target 82C284 variant and clock-generation
  contract. Model its analog `RES`/VCC power-up qualification and PCLK phase
  behavior; the current reset slice is standalone, and the connected CPU test
  still supplies conditioned RESET and both clocks separately.
- Source the complete 80287 transaction contract before implementing
  PEREQ/PEACK/BUSY/ERROR.

## Core beat interface

`intel_80286` has an opt-in `NATIVE_BEATS` parameter. The default value `0`
preserves the established byte-transaction behavior. With `NATIVE_BEATS=1`,
`bus_wdata_o` and `bus_rdata_i` carry lane-aligned D15:D0 values,
`bus_beat_bytes_o` reports the one or two bytes completed by the current
`bus_ready_i` handshake, and `bus_size_o` reports the remaining bytes in the
logical memory or I/O operation. Fetches and descriptor-engine transfers stay
one byte. An even-addressed data operation with at least two bytes remaining
uses both lanes; an odd-addressed byte uses D15:D8 and the following even
address is scheduled independently. The owner captures the full write lanes,
address and context across READY waits. The core advances its address, byte
index and remaining count only when READY completes the reported beat.

The descriptor engines remain byte-oriented; the core aligns their byte data
to the physical address lane and selects the returned lane before accepting
each byte. CPU and event data operations use the same beat-size rule. Tests in
`tb/native_core.cpp` check even words, odd-word split ordering, lane selection
and exact data against the completed CPU transactions.

`intel_80286_native_cpu` now instantiates `intel_80286` in native-beat mode
with `intel_80286_native_bus`. The wrapper connects external `READY#` to core
completion, transfers both data lanes, routes INTR/NMI and the two-cycle INTA
vector handshake, and exposes address, status, lane, LOCK#, and HLDA outputs.
A pin-level Verilator test exercises even and odd words, READY waits, hardware
INTR/INTA, IVT reads, the interrupt frame and IRET. A separate
`intel_80286_82288` instance decodes CPU status and emits the controller strobes
using the external 2x clock; the connected pin test checks every exercised
memory, I/O and INTA command output. Its C++ clock driver places one full
processor-clock period across two external CLK periods, with the processor
clock rising on the first external rising edge in each simulated pair.

This wrapper is not a complete hardware-timing implementation. Its `clk_i`
is already the 80286 processor clock and its `clk_2x_i` is supplied separately;
the wrapper does not derive or phase-lock these clocks. RESET pulse and
deassertion timing are not modeled. The connected test checks a conditioned
RESET pulse and first-fetch address under its selected phase. Core LOCK-prefix
memory transfers and automatic memory XCHG now drive the controller; automatic
descriptor-table and processor-extension locks remain open. MULTIBUS timing,
the sourced 80287 interface and physical/electrical qualification also remain
open. The default
`NATIVE_BEATS=0` path remains useful for functional tests and is not evidence
of native pin behavior. Integration and lock results, exact source hashes and
reproduction commands are recorded in the native CPU, native-clock, LOCK and
82288 reports.
