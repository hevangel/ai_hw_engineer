# Independent oracle and vector generator

`../scripts/gen_vectors.py` is an independent Python model of the documented
Am9512 stack, format and commands. It is derived from the 1980 AMD Am9500
guide chapter, not from the RTL. It writes `../work/vectors.txt` with one line
per test:

```
opcode initial_stack expected_stack status name
```

The testbench replays each line through the real top-level bus: it preloads the
16-byte stack, issues the command, waits for END, reads the 16-byte result
stack and the status byte, and checks the stack, status, END, ERR and SVREQ.

## What the model implements

- Single-precision (32-bit) and double-precision (64-bit) unpack/pack.
- Add, subtract, multiply and divide with exact integer arithmetic.
- Round-to-nearest-even using the manual's guard/round/sticky rule.
- Zero as an all-zero exponent field, with the mantissa ignored.
- Status bits S, Z, U, V and D, and the divide-by-zero result rule.
- The documented stack effects for all 16 commands.
- The PTOS single-precision zero special case.
- The reconstruction overflow/underflow result convention.

## Independence and limits

The model is a separate implementation of the documented format, not a
re-read of the RTL. It is useful for catching shared misreadings of the stack
and format, but it is not a hardware oracle. It does not model the original
microcode, execution-time table, analog timing, internal 17-bit stack word or
undocumented silicon behavior. Its overflow/underflow result convention is a
reconstruction assumption because the 1980 chapter specifies the status flags
but not the returned finite encoding.

The vectors are generated deterministically from a fixed seed. The default flow
uses 300 random arithmetic cases plus the directed command cases; the file is
ignored by Git and regenerated by `run_sim.sh`.
