# Sony S-DSP verification

## Contract and evidence

`sony_s_dsp.sv` is an original model of the S-DSP built on its fixed
32-phase schedule per 32 kHz sample: BRR decoding with the four filters,
pitch with modulation, 4-point gaussian interpolation, noise, ADSR and the
five GAIN modes with the hardware rate table, KON/KOFF and ENDX timing, the
stereo main mix with MVOL, and the 8-tap FIR echo with its buffer in audio
RAM, EDL/ESA timing and FLG (reset, mute, echo write disable). The phases
are tables of micro-operations generated by `scripts/gen_tables.py`. The
[specification](../spec/spec.md) lists sources and assumptions A1–A3.

The planned independent oracle is blargg's cycle-accurate `SPC_DSP`
(snes_spc 0.9.0, as carried by snes9x at revision
`1bcc369e89f08243e0a462882fb1f3e42e51de3a`), compared sample by sample
with the RTL by `scripts/run_oracle.sh`. The RTL was written from a
different code base (ares), so the two share only the published algorithm.

## Results (2026-10-27)

Cloud container: Verilator 5.020, Yosys 0.33.

| Gate | Measured result |
|---|---|
| Strict lint | `verilator --lint-only -Wall` passes |
| Gaussian table | `scripts/fetch_oracle.py`: the generated table matches the 512-entry hardware dump in `SPC_DSP.cpp` entry for entry |
| Lock-step oracle | **Not run yet.** It compiles third-party source and is waiting for the owner's approval |
| Synthesis | Generic Yosys synthesis with `-noshare` and `check -assert` pass: 60,863 cells. The default flow's resource sharing creates 276 false combinational loops after ABC |
| Real software (SNES system) | The 9 Peter Lemon sound demos (Axel-F, FFVIIPrelude, ItaloTest, PitchMod, PlayBRRSample, PlayNoise, PlayTwoSong, SpeechSynth, Twinkle) run 300 frames with no micro-op overrun and produce non-silent stereo output |

The sound demos ship no reference recording, so they show only that the
voices, envelopes and mixer produce output; sample accuracy rests on the
oracle gate above.
