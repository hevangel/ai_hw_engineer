# 74x3893: quad Futurebus backplane transceiver (3-state + open collector)

First introduced: Unknown. [Motorola MC74F3893A, "Quad Futurebus Backplane
Transceiver (3 State + Open Collector)", FAST Schottky
TTL](https://archive.org/details/bitsavers_motoroladaFASTandLSTTLData_35934218),
in the Motorola-authored *1992 FAST and LS TTL Data* book. SHA-256:
`96ee048026e187ffe3ca9179b01e06149a8970566bbf52cbdaa1c01988b543e9`.
Description, pinout and logic symbol on PDF page 314 (printed 4-276), logic
diagram and function table on PDF page 315 (printed 4-277), all visually
reviewed. The source is a full datasheet, not a preview. The part is pin and
function compatible with the NSC DS3893A and Signetics 74F3893, interfaces to
"Backplane Transceiver Logic" (BTL) with a reduced 1 V swing, sinks a minimum
of 100 mA on the bus side, and is designed glitch-free during power up/down.

## Native digital contract

This is not a conventional bidirectional multiplexer: driver and receiver are
independent single-direction paths with split TTL ports, and the driver is a
NAND-gated open collector. `d_in[3:0]` observes TTL data inputs D0..D3, and
`de` is the active-high Data Enable. `io_in[3:0]` observes the resolved
bus-side I/O pins I/O0..I/O3 (1 = line released by every driver, 0 = asserted
low). The four data inputs are NANDed with DE, per both the prose and the
logic diagram: each I/O pin sinks its line exactly when `de=1` and its
`d_in` bit is 1, and is released otherwise. `io_drive[3:0]` carries the
per-pin open-collector sink flags following the 16246 precedent (flag 1 = pin
actively sinking, flag 0 = released); `io_out[3:0]` is always zero and board
adapters ignore it.

`re_n` is the common Receive Enable, active low exactly as drawn (the RE pin
is RE-with-overbar). The four TTL receiver outputs R0..R3 are inverting
three-state buffers: `r_out = ~io_in` while `re_n=0`, isolated otherwise.
`r_drive` is the scalar bank-enable flag for the single RE-gated receiver
bank. DE and RE are fully independent, reproducing every row of the function
table:

| de | re_n | d_in bit | io line        | r_out bit | mode                           |
|----|------|----------|----------------|-----------|--------------------------------|
| 1  | 0    | 0        | released       | 0         | Transmit to Bus                |
| 1  | 0    | 1        | sunk low       | 1         | Transmit to Bus                |
| 1  | 1    | 0        | released       | high-Z    | Receiver 3-State, Transmit     |
| 1  | 1    | 1        | sunk low       | high-Z    | Receiver 3-State, Transmit     |
| 0  | 1    | x        | released       | high-Z    | (driver released, R off)       |
| 0  | 0    | x        | released (input) | ~io_in  | Receive, I/O = Inputs          |

Note the quirk the table records: with DE high the driver keeps transmitting
regardless of RE, so a transmitter with its own receivers disabled must rely
on the far end to echo; and with DE low the driver releases the bus for
whatever else drives it, including the module's own readback.

ASSUMPTION: Externally resolved powered logic; a released I/O line is observed
high only because the bus bias resolves it before the pin, and the receiver
threshold region (VTH 1.475..1.625 V) is an electrical detail. The 1 V
reduced swing, series driver diode, < 5 pF loading, bus/logic ground
isolation, power-up/power-down glitch-free output behavior, sink current and
timing are analog/electrical characteristics and are omitted.
