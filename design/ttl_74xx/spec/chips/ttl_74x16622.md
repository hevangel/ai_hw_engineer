# 74x16622: 18-bit LVTTL-to-GTL/GTL+ bus transceiver

**Manufacturer source:** Texas Instruments SN74GTL16622A, SCBS673F (August 1996, revised April 2005), [official TI datasheet](https://www.ti.com/lit/ds/symlink/sn74gtl16622a.pdf); the description and package information are on PDF pages 1-2 and the logic diagram on PDF page 3 of the cached manufacturer PDF, SHA-256 `d17649898935f53b6a01b3387615d70e0370e8e76ca3a6a02116c9564228ff29`. The function table is on PDF page 2.

An 18-bit registered bus transceiver providing LVTTL-to-GTL/GTL+ and
GTL/GTL+-to-LVTTL translation, partitioned as two separate 9-bit transceivers
with individual clock-enable controls and D-type flip-flops with qualified
storage.

## Logical contract

The A port is LVTTL (push-pull); the B port is GTL/GTL+ and sinks only (the
source lists 100 mA low-state B-port current and no B-port high-state drive).
`a_in[17:0]`/`b_in[17:0]` observe package A1..A18/B1..B18; bank 1 is bits
[8:0] (package 1A/1B) and bank 2 is bits [17:9] (package 2A/2B). `ceab[0]`/
`ceba[0]` qualify bank 1 and `ceab[1]`/`ceba[1]` qualify bank 2. CLKAB, CLKBA,
OEAB, and OEBA are common to both banks. `a_out`/`a_drive` carry the B-to-A
push-pull output state; `b_drive` is the A-to-B low-only sink mask.

Per the function table (A-to-B shown; B-to-A similar):

| CEAB | OEAB_n | CLKAB | B output | Mode |
|---|---|---|---|---|
| X | 1 | X | released | Isolation |
| 0 | 0 | rising | A captured | Clocked storage of A data |
| X | 0 | steady H or L | B0 | Hold |
| 1 | 0 | X | B0 | Qualified storage inhibited |

A rising edge captures only while CEAB is low. CE high holds the stored data
but does not itself disable outputs — output state obeys OEAB/OEBA alone, so
stored data stays visible with the clock inhibited. OEAB and OEBA low
simultaneously is not recommended by the source; this model lets both banks
drive and the board model resolves the contention.

VREF is an analog reference and is omitted from this pure-digital contract.

ASSUMPTION: Native setup/hold windows are not modeled; register contents power
up unspecified. `b_drive` is an explicit low-only sink indication; board models
must supply termination pullups, resolve the bus, and only then feed `b_in`.
Masked outputs are zero and ignored by board adapters.
