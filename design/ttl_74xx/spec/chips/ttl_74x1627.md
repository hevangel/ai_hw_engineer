# 74x1627: 18-bit LVTTL-to-GTLP bus transceiver with source synchronous clock outputs

**Manufacturer source:** Texas Instruments SN74GTLPH1627, SCES356B (June 2001, revised September 2001), in the official [TI GTLP design guide SCED004A](https://www.ti.com/lit/ug/sced004a/sced004a.pdf), printed pages 3-97 to 3-102; the package pinout is on book PDF page 160, the logic diagram on PDF page 163, and the complete function tables on PDF page 164. Book PDF SHA-256: `414fb09c44deff6897c9fdf90ea9b59f9f592e5f78067cb4d65d80018799a995`. The source pages are explicitly stamped **PRODUCT PREVIEW**; the modeled behavior is limited to those tables.

A high-drive (100 mA) 18-bit bus transceiver for LVTTL-to-GTLP translation with
a source-synchronous clock path: the LVTTL system clock (SYSCLK) is forwarded
to the GTLP SSCLK bus and to the LVTTL CLKOUT output, and in source-synchronous
receive mode the GTLP SSCLK clock is converted and echoed on CLKOUT. CMS
switches between source-synchronous and clock-synchronous operation.

## Logical contract

The A port is LVTTL (push-pull); the B port is GTLP and sinks only (100 mA
low-state drive, no high-state drive). `a_in[17:0]`/`b_in[17:0]` observe
package A1..A18/B1..B18. `a_out`/`a_drive` are the push-pull A output state;
`b_drive` is the low-only sink mask for the B port. `ssclk` observes the
resolved external GTLP clock bus present on the bidirectional SSCLK pin, and
`ssclk_sink` sinks that bus low while SYSCLK is high during the forwarding
phases described below. `clkout`/`clkout_drive` are the LVTTL CLKOUT state.

Control pins keep native polarity: `oe_n` (OE, active low) enables the 18 data
bits, `dir` low selects A-to-B and high selects B-to-A, `cms` low selects
source-synchronous mode and high clock-synchronous mode, and `ckoen_n` (CKOE,
active low) selects the registered data path with clock outputs enabled
versus the transparent data path with clock outputs disabled.

Mode table (from the source function tables):

| CKOE_n | OE_n | CMS | DIR | Data output | SSCLK | CLKOUT |
|---|---|---|---|---|---|---|
| 0 | 0 | X | 0 | registered A (B port) | sinks SYSCLK | SYSCLK |
| 0 | 1 | X | 0 | released, A register still captures | sinks SYSCLK | SYSCLK |
| 1 | 0 | X | 0 | transparent A (B port) | released | released |
| 1 | 1 | X | X | released | released | released |
| 0 | 0 | 0 | 1 | registered B (A port) | input | SSCLK |
| 0 | 1 | 0 | 1 | released, B register still captures | input | SSCLK |
| 0 | 0 | 1 | 1 | registered B (A port) | sinks SYSCLK | SYSCLK |
| 0 | 1 | 1 | 1 | released, B register still captures | sinks SYSCLK | SYSCLK |
| 1 | 0 | X | 1 | transparent B (A port) | released | released |

Storage: the A-to-B register captures A on SYSCLK rising edges; the B-to-A
register captures B on SSCLK rising edges in source-synchronous mode and on
SYSCLK rising edges in clock-synchronous mode. In data isolation (OE high,
CKOE low) both registers continue to capture while the data outputs stay
released, exactly as the description states. Registered data outputs show the
stored value; with CKOE high the data path is transparent instead.

ASSUMPTION: The source is a PRODUCT PREVIEW; behavior beyond the printed
function tables is not certified. Native setup/hold windows and the FSTA
flexible-setup-time delay are analog features outside this contract and are
omitted, as are ERC and VREF/BIAS VCC. Register contents power up unspecified.
Sink masks are explicit low-only drive indications; board models must supply
termination pullups, resolve the buses (including the SSCLK bus observation
fed back to `ssclk`), and only then feed `a_in`/`b_in`.
