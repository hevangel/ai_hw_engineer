# 74x3390: Octal 2:1 multiplexer bus switch

**Status:** source-reviewed passive digital topology model.

It provides two independently enabled 8-bit paths to a shared third bus, including a mode that passively joins all three ports. This model preserves the source's digital connectivity controls and bidirectional paths. It is a passive switch network, not a directed Boolean mux.

## Controls and topology

AEN_n and BEN_n are independent active-low bus-switch enables. With both low, all three ports join through the per-lane C node; the device does not provide direction isolation.

| AEN_n | BEN_n | Connections per lane |
|---:|---:|---|
| 1 | 1 | A, B, and C disconnected |
| 0 | 1 | A connected to C; B isolated |
| 1 | 0 | B connected to C; A isolated |
| 0 | 0 | A, B, and C are one common component |

Port mapping: Port 0 is A0–A7, port 1 is B0–B7, and port 2 is C0–C7; lane k is flattened bit k in each port. Flattened bus offset details: A=indices 0–7; B=8–15; C=16–23.

## Model contract and limits

`external_data` and `external_drive` describe external strong digital drivers only; do not feed a prior resolved value back as a new source. `resolved`, `valid`, `conflict`, and `weak_drive` use the flattened port ordering above. Ports joined by enabled switch paths form one connected component in each lane. Equal strong drivers resolve normally. Opposite strong drivers set `conflict=1`, `valid=0`, and masked `resolved=0` on every member. A component with no external source is invalid; this device supplies no modeled weak pull, so `weak_drive` is always zero.

ASSUMPTION: All external values are already valid Boolean logic levels and controls are settled. The manufacturer describes n-channel FET paths and a common C bus. Each enabled port-to-C path is modeled as ideal bidirectional digital connectivity; when both are enabled, A, B, and C form one component. This omits resistance, bias requirements, voltage limits, timing, and transient effects. The library applies its global passive-network rule: resolve the whole connected topology once from external sources rather than cascading already-resolved outputs.

## Verification

The self-checking test independently builds connected components from the source-derived switch table, then checks all four control combinations, floating lanes, one-source propagation from each port and lane in both polarities, opposite-source conflicts for every port pair, and 96 deterministic mixed-drive patterns per control mode. It compares both endpoints and checks `valid`, `conflict`, `resolved`, and `weak_drive`.
