# 74x2032: 9-bit TTL/BTL competition transceiver

First introduced: Unknown. TI published this part only as PRODUCT PREVIEW
advance data, so no first-shipment date is established by the source.
[Texas Instruments SN54FB2032 / SN74FB2032, "9-Bit TTL/BTL Competition
Transceivers", November 1991, revised October
1992](https://archive.org/details/bitsavers_tidataBookiCMOSTechnologyDataBook_40217042),
in the TI-authored *1992 ABT Advanced BiCMOS Technology Data Book*.
SHA-256: `1605f2416d37ec4f244a19d294e519a42398cde2e8e180ab64c8fae762f2433a`.
Description and pinout on PDF page 701 (printed 7-15), function tables on PDF
page 702 (printed 7-16), functional block diagram on PDF page 703 (printed
7-17), all visually reviewed. The part targets IEEE 1194.1-1991 (BTL) and
IEEE 896.2-1991 (Futurebus+). The nine bits are eight data bits plus one bus
parity bit per port.

## Contradictory source tables (not implemented)

The function-table page (PDF 702, printed 7-16) reproduces the 'FB2031's
STORAGE MODE TABLE (columns `LCA, LCB`) and SELECT FUNCTION TABLE (columns
`SEL1, SEL0`), but the 'FB2032 pinout (PDF 701, printed 7-15) has **no LCA,
LCB, SEL1 or SEL0 pins**. Those tables contradict the part's own pinout; they
are preview copy errors carried over from the 'FB2031 entry and are NOT
implemented. Only the physically pinned controls are modeled: OEA, OEB,
OEB(bar), LE, COMPETE, AP, BP, WIN. The pins LCA, LCB, SEL1 and SEL0 are never
invented here, and no latch/flip-flop/thru selection is fabricated for a part
whose only storage control is LE.

## Native digital contract

`a_in[8:0]` observes TTL pins with bit 0 = A1 through bit 7 = A8 (A8 is the
most significant arbitration bit) and bit 8 = AP (bus parity). `b_in[8:0]`
likewise observes resolved BTL pins B1..B8 plus BP (1 = line released by every
driver, 0 = asserted low by at least one driver). `oea` is the active-high
A-port output enable. `oeb` (active high) and `oeb_n` (active low) jointly
enable the B port, matching all six transceiver function-table rows: B drives
only while `oeb=1` and `oeb_n=0`; `oea=0` isolates the A outputs; with both
conditions met, both directions transfer simultaneously. `le` latches the
A-port data per the description: LE high holds the latches, LE low makes them
transparent. `compete` is active low (protocol logic active when low). `win`
is the arbitration result output. `a_out[8:0]` is three-state A data with
scalar bank-enable flag `a_drive`; `b_drive[8:0]` carries per-pin
open-collector sink flags (16246 precedent: 1 = sinking, 0 = released) and
`b_out[8:0]` is always zero.

Transfers are inverting between ports: the B port carries "A-bar data" (a
latched A bit of 1 sinks its B line) and the A port emits "B-bar data"
(real-time `a_out = ~b_in`; the B-to-A path is transparent, it has no latch).
Both the B drivers and the arbitration logic consume the LE-latched A data.

Competition, per the description and the block-diagram chain: with `compete`
low the device compares its latched arbitration number (A8..A1, MSB first)
against the number being sunk on the wired-AND B arbitration bus. Data bit k
survives iff the latched A bit is 1 or the observed B line is released; `win`
is high iff all eight data bits survive, and each data-bit driver is
additionally gated by the survival of every more significant bit, so a module
that stops surviving releases its less significant lines. On a two-module bus
this network settles with `win` asserted on exactly the module holding the
greater number, which is the prose's semantics: the loser detects the
contested more-significant 1 on the bus, releases its lines below that point,
and the winner's number remains asserted on the B bus for readback through
OEA. Two modules with equal numbers both assert `win` (a wired-OR bus cannot
express strict inequality); the Futurebus+ protocol layer resolves ties
outside this device. `win` is forced low while `compete` is high. BP is driven
like a ninth data bit from latched AP without chain gating (two-input AND in
the diagram); during a competition the winner's parity therefore dominates the
bus, matching "the winning module may assert BP low if its parity bit (AP) is
high".

ASSUMPTION: WIN comparison covers the eight data bits only; AP is excluded
because the prose defines the arbitration number as A8..A1 and describes AP
separately as the parity bit.

ASSUMPTION: The driver chain gating (and hence winner-takes-the-bus release)
is active only while COMPETE is low; with COMPETE high the part behaves as a
plain latching transceiver and every enabled B line carries `~a_lat`.

ASSUMPTION: `win` is not gated by OEA/OEB; the description has OEB high and
OEB_n low during a competition, so the enables do not qualify the arbitration
result itself. Because a set latched bit forces its own survival term to 1, a
module's own sinks can never disturb its comparison.

ASSUMPTION: Externally resolved powered logic. JTAG pins are no-connects in
this product-preview version (TMS and TCK not connected, TDI shorted to TDO)
and are omitted, as are BIAS Vcc, BG Vcc, BG GND, bias networks, edge rates,
sink current, Vcc < 2.5 V power-off isolation, thresholds and timing. Latch
power-up contents are unspecified. As PRODUCT PREVIEW data the electrical
values are design goals; the block diagram's RC pin numbers agree with the
pinout page, so the pinout and the prose are treated as authoritative and the
contradictory copied tables above are rejected.
