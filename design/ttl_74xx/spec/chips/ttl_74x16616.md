# 74x16616: 17-bit LVTTL-to-GTL/GTL+ universal bus transceiver with buffered clock outputs

**Manufacturer source:** Texas Instruments SN74GTL16616, SCBS481H (June 1994, revised August 2001). Function table and description read from the official [TI GTLP design guide SCED004A](https://www.ti.com/lit/ug/sced004a/sced004a.pdf), printed pages 2-23 to 2-34 (pinout book PDF page 44, function table and description PDF page 45, logic diagram PDF page 46); the logic diagram was additionally verified against the standalone device PDF (cached copy SHA-256 `c045a77e0e90b063576bb084fc210a7393b8ad5db459871408cabfd8848e4b9b`, diagram on its page 3). Book PDF SHA-256: `414fb09c44deff6897c9fdf90ea9b59f9f592e5f78067cb4d65d80018799a995`.

A 17-bit universal bus transceiver (UBT) providing LVTTL-to-GTL/GTL+ and
GTL/GTL+-to-LVTTL translation. Its combined D-type flip-flops and D-type latches
give transparent, latched, clocked, and clock-enabled modes identical to the
'16601 function, plus a buffered clock path: a copy of CLKAB at GTL/GTL+ levels
on CLKOUT and conversion of a GTL/GTL+ clock at CLKIN.

## Logical contract

The A port is LVTTL (push-pull); the B port is GTL/GTL+ and sinks only (the
source lists 80 mA low-state B-port current and no B-port high-state drive).
`a_in[16:0]`/`b_in[16:0]` observe package A1..A17/B1..B17. `a_out`/`a_drive`
carry the B-to-A push-pull output state; `b_drive` is the A-to-B low-only sink
mask. Data flow per direction is identical to the '16601: `oeab_n`/`oeba_n`
(active low) enable outputs, `leab`/`leba` follow data transparently while high
and capture on their falling edges, `clkab`/`clkba` capture on rising edges, and
`ceab_n`/`ceba_n` (active low, overbarred CĒAB/CĒBA in the source) qualify the
clocked capture. Per the function table (A-to-B shown; B-to-A similar):

| CEAB_n | OEAB_n | LEAB | CLKAB | B output | Mode |
|---|---|---|---|---|---|
| X | 1 | X | X | released | Isolation |
| 0 | 0 | 0 | 1 | B0 | Latched storage of A data |
| 0 | 0 | 0 | 0 | B0 | Latched storage of A data |
| X | 0 | 1 | X | A live | True transparent |
| 0 | 0 | 0 | rising | A captured | Clocked storage of A data |
| 1 | 0 | 0 | X | B0 | Clock inhibit |

Buffered clock: `clkout_sink` sinks the GTL clock bus low while CLKAB is high
and OEAB is low (the source logic diagram drives CLKOUT, pin 31, from CLKAB
through an open-drain gate enabled by OEAB); otherwise the bus is released to
termination. `clkin` (pin 26) is the observation of the resolved external GTL
clock bus: board models must connect it to the resolved CLKOUT net rather than
driving it as an independent clock. CLKBA remains a separate native input for
the B-to-A data path, exactly as in the function table.

VREF is an analog reference and is omitted from this pure-digital contract.

ASSUMPTION: This model uses the shared library UBT abstraction: the transparent
and stored output paths collapse into one state element per direction that
tracks its input while LE is high and holds the last transparent value after LE
falls. Native qualified LE transitions (CLKAB high before LEAB falls) are not
separately observable, and native setup/hold windows are not modeled. Register
contents power up unspecified. The internal destination of the CLKIN LVTTL
conversion beyond the resolved-bus observation is not separately pinned in the
function table and is not modeled; the clock path contract above is the complete
modeled behavior. Masked outputs are zero and ignored by board adapters.
