# 74LS681: 4-bit parallel binary accumulator

**First introduced:** Unknown. The TI source in this library is dated January 1981 and revised April 1985; that publication date does not establish the device's first-introduction year.

**Manufacturer source:** Texas Instruments, *The TTL Data Book, Volume 2* (1985), types SN54LS681/SN74LS681, datasheet D2422. [Archive item and full scanned book](https://archive.org/details/bitsavers_tidataBookVol2_45945352); [functional block diagram, printed page 3-1290](https://archive.org/details/bitsavers_tidataBookVol2_45945352/page/n1340/mode/1up); [function tables, printed page 3-1291](https://archive.org/details/bitsavers_tidataBookVol2_45945352/page/n1341/mode/1up). The title page for this datasheet states “January 1981 – Revised April 1985.”

This device combines a four-bit arithmetic/logic unit with a synchronous Word A register and a Word B register that can accumulate, load, and shift. Its parallel bus and two directional serial ports make it a compact datapath part for a board-level processor or calculator. The 1985 TI description says the carry inputs and P/G outputs support cascading wider words.

## Normalized digital interface

The RTL models logical levels and native synchronous behavior. It does not model TTL voltages, propagation delays, output drive strength, or analog bus resolution. The bidirectional package pins are represented as split input/output signals with explicit positive-logic drive flags. `io_out` is meaningful when `io_drive` is high; likewise for the serial ports. `word_a` and `word_b` expose stored state for system-level observation, and `f` exposes the internal ALU result even when the package I/O bus is disabled.

The chip has no reset input. Word A, Word B, and the serial output state therefore have unspecified power-up values. Initialize a simulation by loading the registers through register-selection modes.

| RTL signal | Meaning |
|---|---|
| `clk` | Rising-edge clock. Register behavior is specified at the low-to-high transition. |
| `m` | ALU mode: `0` arithmetic (Table 1), `1` logic (Table 2). |
| `asel[2:0]` | ALU function selection AS2:AS0. |
| `cn` | Active-high carry input. |
| `rs[2:0]` | Register selection RS2:RS1:RS0 (Table 3). |
| `io_in[3:0]` | Data presented to the parallel I/O pins when a register-load mode is selected. |
| `li_in`, `ri_in` | Logical levels presented to the LI/RO and RI/LO pins, respectively. They are sampled in the shift modes where those pins are inputs. |
| `io_out[3:0]`, `io_drive` | Parallel bus value and positive drive flag. The bus drives the current ALU result outside the two parallel-load modes. |
| `li_ro_out`, `li_ro_drive` | LI/RO serial output value and positive drive flag. |
| `ri_lo_out`, `ri_lo_drive` | RI/LO serial output value and positive drive flag. |
| `f[3:0]` | Internal four-bit ALU result. |
| `p_bar`, `g_bar` | Active-low propagate and generate outputs, matching the bars on the TI logic symbol. Their Boolean equations are a documented modeling assumption below. |

| `word_a[3:0]`, `word_b[3:0]` | Current stored register values. |

## Tables 1 and 2: ALU functions

All vectors are four bits. “With carry” is `cn=1`; “no carry” is `cn=0`. The logic table's “PLUS 1” means add one to the four-bit logical result, modulo 16. Equivalently, for logic mode the result is `logic_base + cn`.

| M | AS2:AS0 | `cn=1` | `cn=0` |
|---:|:---:|---|---|
| 0 | 000 | `4'h0` | `4'hF` |
| 0 | 001 | `B - A` | `B - A - 1` |
| 0 | 010 | `A - B` | `A - B - 1` |
| 0 | 011 | `A + B + 1` | `A + B` |
| 0 | 100 | `B + 1` | `B` |
| 0 | 101 | `~B + 1` | `~B` |
| 0 | 110 | `A + 1` | `A` |
| 0 | 111 | `~A + 1` | `~A` |
| 1 | 000 | `4'h1` | `4'h0` |
| 1 | 001 | `(A ^ B) + 1` | `A ^ B` |
| 1 | 010 | `~(A ^ B) + 1` | `~(A ^ B)` |
| 1 | 011 | `4'h0` | `4'hF` |
| 1 | 100 | `(A & B) + 1` | `A & B` |
| 1 | 101 | `(~A | B) + 1` | `~A | B` |
| 1 | 110 | `(~A & B) + 1` | `~A & B` |
| 1 | 111 | `(A | B) + 1` | `A | B` |

Arithmetic and logic results wrap to four bits. The carry output is the carry from the same selected operation. For the arithmetic rows, the RTL maps each operation to a four-bit addition with `cn`. For logic mode it adds `cn` to the selected logic vector.

**ASSUMPTION — carry look-ahead equations:** the TI block diagram identifies active-low P and G outputs and Cn+4, and describes them as carry-look-ahead signals, but the cited function tables do not give their Boolean equations. The model maps the selected result to operands `X` and `Y` and uses `P = AND_i(X_i OR Y_i)`, `G = carry(X + Y)` with `cn=0`, and `Cn+4 = G OR (P AND cn)`. In logic mode it uses `X=0` and `Y=logic_base`, so `cn4` is the carry from `logic_base + cn`. The interface exposes `p_bar=~P` and `g_bar=~G` to preserve the manufacturer's active-low pin polarity. This is a transparent logical model assumption, not a claim that TI explicitly specifies those equations in Table 1 or Table 2.

## Table 3: register modes

All state updates happen on `posedge clk`. Unless a mode says otherwise, the corresponding register holds its value. Serial outputs are sampled from the pre-edge Word B state so their post-edge values match Table 3.

| `rs` | Mode | State update at the rising edge | Parallel and serial pin directions |
|:---:|---|---|---|
| 000 | Accumulate | `word_b <= f` using the pre-edge ALU result; Word A holds. | I/O drives `f`; both serial ports are disabled. |
| 001 | Load B | `word_b <= io_in`; Word A holds. | I/O is input; both output-drive flags are low. |
| 010 | Left shift logical | `word_b <= {li_in, word_b[3:1]}`; Word A holds; RI/LO captures old `word_b[0]`. | LI/RO is input; RI/LO drives the captured bit; I/O drives `f`. |
| 011 | Left shift arithmetic | `word_b <= {word_b[3], li_in, word_b[2:1]}`; Word A holds; RI/LO captures old `word_b[0]`. | LI/RO is input; RI/LO drives the captured bit; I/O drives `f`. |
| 100 | Right shift logical | `word_b <= {word_b[2:0], ri_in}`; Word A holds; LI/RO captures old `word_b[2]`. | RI/LO is input; LI/RO drives the captured bit; I/O drives `f`. |
| 101 | Right shift arithmetic | `word_b <= {word_b[3], word_b[1], word_b[0], ri_in}`; Word A holds; LI/RO captures old `word_b[1]`. | RI/LO is input; LI/RO drives the captured bit; I/O drives `f`. |
| 110 | Hold | Word A and Word B hold. | I/O drives `f`; both serial ports are disabled. |
| 111 | Load A | `word_a <= io_in`; Word B holds. | I/O is input; both output-drive flags are low. |

The unusual right-shift arithmetic source mapping is transcribed literally from Table 3: LI/RO presents QB1 before the edge, and after the edge Word B is `{QB3, QB1, QB0, ri}` while LI/RO presents QB1n. It is not replaced with a generic sign-extending shift convention.
