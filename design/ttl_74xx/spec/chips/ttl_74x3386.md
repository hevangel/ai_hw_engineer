It supplies two independently switched 5-bit paths that can be straight-through or crossed, an important board-level bus-routing function. This model preserves the source's digital connectivity controls and bidirectional paths. It is a passive switch network, not a directed Boolean mux.

## Controls and topology

Native BE is active-high disconnect; BX high selects the crossed exchange. Data grouping is 5 bits per A1, A2, B1, and B2 port.

| BE | BX | Connections per lane |
|---:|---:|---|
| 0 | 0 | A1–B1 and A2–B2 |
| 0 | 1 | A1–B2 and A2–B1 (exchange) |
| 1 | X | All four ports isolated |

Port mapping: Port 0 is A1 (five lanes), port 1 is A2, port 2 is B1, port 3 is B2; lane k is flattened bit k in each port. Flattened bus offset details: A1=indices 0–4; A2=5–9; B1=10–14; B2=15–19.

## Model contract and limits

`external_data` and `external_drive` describe external strong digital drivers only; do not feed a prior resolved value back as a new source. `resolved`, `valid`, `conflict`, and `weak_drive` use the flattened port ordering above. Ports joined by enabled switch paths form one connected component in each lane. Equal strong drivers resolve normally. Opposite strong drivers set `conflict=1`, `valid=0`, and masked `resolved=0` on every member. A component with no external source is invalid; this device supplies no modeled weak pull, so `weak_drive` is always zero.

ASSUMPTION: All external values are already valid Boolean logic levels and controls are settled. The source describes a bidirectional FET path. The model resolves all ports connected by the selected passive topology; it is not a directed logic mux. TI specifies a 5-ohm on-resistance and extended analog input range, but the Boolean model treats an enabled switch as ideal zero-delay connectivity and omits voltage limits, resistance, timing, and transient behavior. The library applies its global passive-network rule: resolve the whole connected topology once from external sources rather than cascading already-resolved outputs.

## Verification

The self-checking test independently builds connected components from the source-derived switch table, then checks all four control combinations, floating lanes, one-source propagation from each port and lane in both polarities, opposite-source conflicts for every port pair, and 96 deterministic mixed-drive patterns per control mode. It compares both endpoints and checks `valid`, `conflict`, `resolved`, and `weak_drive`.
