# Final Design Report: AMD Am9518 Data Ciphering Processor

## 1. Executive Summary

The Am9518 reconstruction is complete and passing its full verification
flow: Verilator lint (`--lint-only -Wall`) clean, all three SymbiYosys
tasks (bmc depth 40, prove depth 12, cover depth 60) pass, ten simulation
suites totalling 1352 directed checks pass with zero failures against an
independently anchored DES oracle, and Yosys synthesis completes to a
generic gate netlist.

The oracle chain is external at every link: test vectors were generated by
third-party `pyDes` and cross-checked bit-for-bit against OpenSSL's
legacy-provider DES before being pinned, and the published anchors
(NBS all-zero KAT, the FIPS-era "Now is t" example, and AMD's own 1985
interface-guide hardware test) are re-verified at every regeneration.

## 2. Design Overview

- Module: `amd_am9518_top` (with `des_core` and generated FIPS 46 tables)
- Path: `design/amd_am9518/`
- Status: functional reconstruction; nanosecond AC parameters out of scope
- Date: 2026-11-13

Implemented behavior (all source-backed in `spec/spec.md`):

- Multiplexed Control Mode master port: MAS-latched MP2/MP1 register
  addressing per datasheet Figure 1, MDS-strobed writes, MCS/MR/W-gated
  tri-state reads.
- Direct Control Mode: AUX5-S/S, AUX6-E/D, AUX7-K/D implicit command
  sequences per Figure 3, with AUX2-BSY/AUX3-CP status mirrors.
- All 23 documented command codes plus undefined-code ignore behavior.
- ECB, CBC and 8-bit CFB ciphering in both directions; IVE/IVD chaining
  registers with clear and encrypted loads and clear/encrypted readback.
- Clear (aux/master) and encrypted key loads with datasheet-faithful
  parity checking: entry checks on clear loads, post-decryption checks on
  encrypted loads, PAR latest-byte and LPAR latched semantics.
- Hardware reset (MAS·MDS), software reset, abort-on-new-command, mode-
  register-write reset, and the five-clock post-reset command blackout.
- Slave port with Figure 6 flag association across all six non-reserved
  mode rows; write-while-full input disregard; three-state empty output.
- Datasheet pipeline timing: 8 clocks/block in, 5-clock flag offsets,
  18-clock algorithm window (one DES round per clock), 8 clocks out.

### 3.2 Formal Verification Results

`formal/amd_am9518.sby`, tasks bmc (depth 40, smtbmc, 31:49 wall), prove
(depth 12 k-induction, 4 s), cover (depth 60, 2 s, all covers reached).
All three tasks pass (`=== formal complete: all tasks passed ===`).

| Property set | Task | Result |
|--------------|------|--------|
| P7 FIFO bounds + pop-only-when-non-empty | bmc + prove | PASS |
| P8 engine-start preconditions (session, EMK) | bmc + prove | PASS |
| Engine start-while-idle contract, done/cnt correlation | bmc + prove | PASS |
| Covers: command completion, ECB/CBC/CFB activity, parity error, hardware reset, encrypted-load decrypt, auxiliary key entry | cover | 8/8 reached |

DES algorithm correctness is established by simulation against the
independent oracle (see `plans/formal_plan.md` for the boundary rationale);
formal covers the datapath bookkeeping and FSM discipline. During formal
bring-up the free-input state space exposed one real FSM hole that the
directed harness could not reach: command-driven DES starts (Read-IV,
encrypted loads) could fire while the engine was still busy. The RTL now
defers those starts until the engine is idle (`dec_pend_q`/`encout_pend_q`),
which also makes the behavior correct for real hosts that issue commands
mid-cipher.

### Verification defects found and fixed during bring-up

Recorded for the escaped-defect ledger discipline — all were caught by the
design's own verification suite before review, with the oracle
disambiguating shared misreadings:

1. DES key schedule consumed subkeys before the round rotation
   (K_r = PC2(C_r D_r) requires the rotation first); caught immediately by
   random-vector diff against pyDes/OpenSSL because the all-zero anchor
   key masked it.
2. S-box 7 rows 3–4 corrupted in the first hand-typed table; replaced all
   tables with generator-emitted FIPS text and added the oracle
   entry-by-entry table diff.
3. CBC decrypt XORed the current cipher block instead of the previous
   chain value; caught by multi-block oracle vectors.
4. CFB decrypt fed the plaintext byte back instead of the cipher byte;
   caught by the multi-byte stream oracle vectors.
5. Encrypted IV-load decode used bit 6 (0xA5 has bit 6 = 0); encrypted IV
   loads took the clear path. Caught by A5/A4 roundtrip vectors.
6. Parity checking ran on entry for encrypted key loads; datasheet
   specifies post-decryption checking. Caught by LPAR status checks.
7. Master-key command (91) stored into the E-key register; caught by the
   aux-key equivalence suite.
8. Figure 6 flag-association rows were swapped; caught by dual-port suites
   and AMD's status-byte expectations.
9. Command-driven DES starts (Read-Encrypted-IV, encrypted key/IV loads)
   could fire while the engine was still busy with a session block; found
   by formal bmc in the free-input space (unreachable by the serialized
   harness), fixed with deferred-start pending flags (see 3.2).
