# Intel 8088 specification

## Scope and authority

This chip implements the documented original Intel 8088 architecture and its native digital minimum/maximum-mode interface. The Intel 8088 was introduced on June 1, 1979 per Intel's [Microprocessor Quick Reference Guide](https://www.intel.com/content/www/us/en/newsroom/resources/microprocessor-quick-reference-guide.html), as a variant of the 8086 designed at Intel's Haifa laboratory: the same 16-bit execution unit behind a bus interface unit with an eight-bit external data bus, a four-byte prefetch queue and adapted prefetch behavior (see the [Intel 8088 overview](https://en.wikipedia.org/wiki/Intel_8088), which sources the Intel *iAPX 86,88 User's Manual*, August 1981, order number 210201-001). Technical authority for the bus interface is the [Intel 8088/8088-2 datasheet](https://www.limpulsion.fr/upload/docs/80882.PDF) (also [mirrored here](https://www.100y.com.tw/pdf_file/34-INTEL-8088,8088-2.pdf)) and the [iAPX 86/88, 186/188 User's Manual — Hardware Reference](https://ardent-tool.com/CPU/docs/Intel/808x/manuals/210912-001.pdf); the shared architecture and the six-byte 8086 counterpart are documented in the [8086 Family User's Manual, October 1979](https://bitsavers.org/components/intel/8086/9800722-03_The_8086_Family_Users_Manual_Oct79.pdf). Ken Shirriff's die-level [8088 prefetch circuitry article](http://www.righto.com/2024/03/8088-prefetch-circuitry.html) documents the physical four-byte queue, its pointers and the flush behavior.

The execution unit RTL is the 8086 member's, referenced by path (`../../intel_8086/src/`) and never duplicated; its specification, encoding ledger and verification evidence are owned by [the Intel 8086 member](../../intel_8086/spec/spec.md) and apply unchanged here, because Intel documents one EU for both chips: "the 8086 and 8088 have the same execution unit (EU) — only the bus interface unit (BIU) is different." The 8088 member owns the BIU, the native pins and everything observable through them. `intel_8088_chip` is the native top; there is no separate functional wrapper because the architectural transaction interface is the 8086 member's `intel_8086` module, shared verbatim. RTL models complete clock phases, not analog voltages, transistor delays or sub-clock setup/hold timing; EU scheduling, instruction cycle counts, prefetch overlap and arbitration latency need not match every original-silicon clock, while the bus phase, lane, wait, ownership and architectural contracts below must hold. This is a chip design and verification environment, without a board, operating system or front panel product.

## Architectural state and instructions

Identical to the Intel 8086: eight 16-bit general registers, four segment registers, a 16-bit IP, `(segment << 4) + offset` physical addresses truncated to 20 bits, little-endian memory and I/O, the complete documented instruction set and the same reset state (CS=FFFFh, IP=0000h, ES/SS/DS=0, FLAGS=F002h, first fetch at FFFF0h). The [8086 member specification](../../intel_8086/spec/spec.md) is the authority for every architectural behavior, the complete documented instruction families, undefined-encoding diagnostics and the interrupt rules; no architectural difference exists between the members. Reset is synchronous: active-high `reset_i` on the native top, active-low `rst_n` inside.

## EU transaction interface

The shared `intel_8086` execution unit presents the same transaction interface as in the 8086 member: `bus_req_o`/`bus_ready_i` completion pairs, aligned 20-bit addresses with `bus_be_o` lane encoding (01 low byte, 10 high byte, 11 whole aligned word), lane-positioned 16-bit data, fetch/first/io/intack/segment classification, `flush_i` queue redirect, `suspend_i` interrupt-entry prefetch suspension and `inhibit_i` odd-word ownership guard. The 8088 BIU consumes that contract unchanged and translates it onto the byte bus; requests remain stable under arbitrary ready stalls, and every 16-bit transaction completes when its last byte cycle completes.

## Native BIU and pins

The prefetch queue holds **four bytes** and is filled **one byte at a time**; the BIU initiates a byte fetch whenever at least one queue byte is free, where the 8086 waits for two free bytes so it can fetch an aligned word in one cycle (Intel *iAPX 86,88 User's Manual*, and [Wikipedia's footnote](https://en.wikipedia.org/wiki/Intel_8088) citing it; die-level confirmation in the [prefetch article](http://www.righto.com/2024/03/8088-prefetch-circuitry.html)). A taken transfer flushes the queue and permanently discards an in-flight prefetch response from the abandoned stream, including repeated redirects before that response completes. Ordinary writes do not invalidate queued instructions. QS reports first byte, subsequent byte or flush during the following clock, with the 8086's QS1:0 encoding.

Every bus cycle transfers **one byte at its full byte address**. A 16-bit EU transaction becomes two ascending byte cycles — the byte at the transfer address first, then the byte at the next address — that complete as one transfer: `eu_ready_o` asserts only at the second cycle's T4, and the bus is never granted away between the two cycles. Odd EU words arrive as two lane transactions from the EU itself (byte at the odd address, then the wrapped byte), which the BIU relays as two ordinary byte cycles protected by the EU's ownership guard. A whole-word read assembles `{high byte, low byte}` before release; byte requests return lane-positioned data.

Bus phases are IDLE, T1, T2, T3, optional Tw, T4, four clocks minimum per cycle as on the 8086. T1 supplies the byte address; READY sampled at T2 determines wait insertion and READY in Tw permits completion; read data is captured at completion and write data is held through T4. Maximum-mode status remains active across an extended wait until completion. S3–S6 multiplex with A16–A19 exactly as on the 8086: S4:S3 encode the segment, S5 follows IF, S6 is zero. Maximum-mode status S2:S0 uses the 8086 encoding (interrupt acknowledge, I/O read/write, halt, code fetch, memory read/write, passive), active until the completion edge.

**Pin differences from the 8086**, per the datasheet and the [Osborne 16-bit Processor Handbook](https://en.wikipedia.org/wiki/Intel_8088):

- AD0–AD7 multiplex address byte 0 and data; **A8–A15 are not multiplexed** and stay valid for the whole bus cycle (they do not switch to status, unlike A16–A19).
- **Pin 34 is SS0, not BHE/S7**: "SSO provides the S0 status information in the minimum mode. This output occurs on pin 34 in minimum mode only", where "DT/R, IO/M, and SSO provide the complete status decoding" ([Intel 8088/8088-2 datasheet](https://www.limpulsion.fr/upload/docs/80882.PDF)); the hardware reference states it "is equivalent to S0 in the maximum mode". The model drives SS0 as the active-low mirror of logical status bit 0 in minimum mode — low during reads, high during writes — and drives pin 34 high in maximum mode (see assumption A7). There is no byte-enable on the eight-bit bus.
- **The memory/I-O status pin is IO/M with reversed sense** versus the 8086's M/IO (high for I/O and interrupt acknowledge, low for memory), chosen for 8085 compatibility.
- Minimum mode otherwise produces ALE, DT/R, DEN, RD, WR, INTA and HOLD/HLDA; maximum mode produces S2:S0, QS, LOCK and bidirectional RQ/GT0/1, with the 8288 generating the command strobes. AD floats throughout INTA; the two-cycle INTA sequence of the 8086 is unchanged (the EU's whole-word dummy acknowledge request is deliberately **not** split into two cycles, because the physical INTA sequence is exactly two bus cycles). Explicit output-enable ports represent floating AD, upper address/status and control pins during ownership loss.

Arbitration follows the 8086 member: requests sampled by T2 may receive ownership at a transfer completion; RQ/GT0 wins simultaneous requests; a pending RQ/GT1 survives the first grant and release; grants cannot split LOCK, interrupt acknowledges, odd words or a word's two byte cycles; ownership requests outrank pending INTR and are honored before the reset-vector fetch when asserted at reset release. Native tests cover these rules independently of instruction vectors.

## Assumption ledger

| ID | Choice, source and validation |
|---|---|
| A1 | GPR reset values are unspecified by Intel; deterministic zero values are an implementation choice inherited from the shared EU. Historical software initializes the registers it needs. |
| A2 | EU scheduling and overlap differ from silicon, and no instruction-cycle-count or electrical timing claim is made for either member. The 8088's byte-bus cycle counts (two cycles per word) are structural, not a timing claim. Architectural vectors run through the native chip in both modes; bus protocol has separate directed tests. |
| A3 | Segment-offset word wrap is required by the 8086 member's physical fixture evidence; the shared EU implements it and the 8088 native tests verify the wrapped bytes cross the byte bus. |
| A4 | Undefined flags have no promised value; the independent oracle's metadata masks them. Division-error stack masks apply only to the two FLAGS bytes, never the return address or other writes. |
| A5 | `fault_o` is a diagnostic outside the native architecture, inherited from the shared EU; undefined/invalid encodings have no general behavioral promise. Historical software must complete without this signal. |
| A6 | The 8086 datasheet arbitration rules protect multi-cycle transfers (the 8086 member documents the unlocked odd-word guard); on the 8088 every aligned word is structurally two bus cycles, and the model extends the same rule by never granting the bus between them. The primary sources do not state 8088-specific word-atomicity wording; the extension is flagged here and exercised by a directed test. |
| A7 | SS0 is modeled as the active-low mirror of logical status bit 0 during owned cycles in minimum mode (the datasheet's "provides the S0 status information" / "equivalent to S0"), including passive intervals where S0 is high; in maximum mode pin 34 is driven high, reading the pinout tables that mark it inactive. No electrical interpretation is claimed; directed tests pin the model's decode against the datasheet trio (IO/M, DT/R, SS0). |
| A8 | The prefetch trigger is modeled as "at least one free queue byte" from the iAPX 86,88 User's Manual rule cited above. The model does not reproduce silicon-internal refill latency (such as the two-cycle queue-resume delay visible in the physical corpus); only architectural state, queue contents and bus transactions are contracted. |
| A9 | The independent-oracle vectors were captured on a physical **AMD D8088** (NMOS, 1982), a licensed second-source 8088, by the [SingleStepTests/8088](https://github.com/SingleStepTests/8088) Arduino8088 harness in maximum mode with an emulated 8288 and no wait states. They are treated as external evidence of 8088 behavior, not of this RTL's internals; port reads return the harness value FFh, which the runner reproduces. |
| A10 | The corpus initial queue is the captured physical queue (at most four bytes); tests are seeded exactly as captured. Prefetch beyond the seeded queue is irrelevant to the architectural comparison because the corpus zeroes no architectural state; the runner serves code fetches beyond the instruction as 90h, matching the corpus convention. |

Sign-off evidence and practical limits are recorded in the [final report](../report/final_report.md). Passing finite tests and safety properties is not an exhaustive proof of every CPU state or electrical implementation.
